> 本文记录 V5 历史实现。2026-10-22 起的学生编码、Post 默认方法及受控实验入口见 [V6 学生编码修复与受控去偏实验说明](V6_学生编码修复与受控去偏实验说明_20261022.md)。

## 1. 当前结论与验证边界

当前代码已能让 CompGCN 沿着本项目的正式数据选择、训练、全测试集推荐、评价、预处理、KPPD 训练中去偏、后处理和结果汇总流程运行。三数据集的消息图均与现有源数据重新生成的结果逐项一致；Algebra2005 的 `baseline`、`in_kppd`、`pre_item`、`post_only` 完成了端到端冒烟检查；Eedi 与 XES 完成 GPU 单批次反向传播，XES 的两层设置也能运行。冒烟检查仅训练一批，**不代表模型效果，不能作为论文实验结果**。

当前统一入口默认在**原 ConvE 打分器前**加入 CompGCN 图传播，并将 Pre(item+KC)+KPPD+Post 配置为完整主方法。第九组去掉 CompGCN 图编码层，仍保留 ConvE 打分器，使用单独批次目录。八个外部对比模型使用各自方法，不会因该骨干开关而改变。

## 2. 最终数据及其用途

三个数据集均使用 `(θ_m, θ_f, rec)=(0.8,0.8,50)`，训练图删除取值为零的**习题遗忘边**。Eedi 使用重新划分的训练/测试学生，另两个数据集沿用原划分。路径由 `Code/codes-New-ConvE/final_dataset.py` 固定并核对清单、人数和图变体：

| 数据集 | 使用的 ER 图（相对于 `Code/Data_Fin_New`） | 训练/测试学生 |
| --- | --- | ---: |
| Eedi | `_resplit_seed20261007/Eedi/forgetting_variants/drop_exfr0p00_rec50/er_graph` | 701 / 234 |
| algebra2005 | `algebra2005/forgetting_variants_rec50/drop_exfr0p00/er_graph` | 430 / 144 |
| XES3G5M-sub-small | `XES3G5M-sub-small/forgetting_variants_rec50/drop_exfr0p00/er_graph` | 727 / 241 |

ER 图中的 `triples.txt` 仍是监督训练数据；`test_triples.txt`、学生划分、Q 矩阵和状态/特征文件供推理及评价使用。CompGCN 另读取同一图目录的 `educational_kg_v2.npz` 作为**消息传播图**，两者不能混为一谈。消息图只纳入训练学生的学生—知识点掌握/非零遗忘边、习题—知识点覆盖边及各自逆边，不把推荐标签 `rec` 放入传播邻接。监督三元组里的非零习题遗忘关系仍参与原训练目标；消息图并没有把习题遗忘边当成直接的传播边。

消息图由 `Code/codes-New-ConvE/educational_kg_v2.py` 构建。已核验三个正式图的现存 NPZ 与源数据重建的 `source`、`target`、`relation`、`strength`、`nentity` 全部一致。训练/测试数据和 EP 校准文件均在本项目目录下，不依赖外部 KG4ER-New 目录。

## 3. 代码如何从数据走到评价

1. **选择与校验数据**：`final_dataset.py` 定位三套正式图、原始交互和 EP readout；正式入口会核查图参数与变体清单。预处理公平图由 `fairness_preprocess_rec_graph.py` 从正式图派生，只改推荐监督边，并复制原消息图；非推荐边与源图一致。
2. **表示与训练**：`run_semantic_conve.py` 根据 `--backbone` 实例化旧 `TwoCKG4ER` 或 `SemanticCompGCN`。CompGCN 从原有学生/习题语义特征形成初始实体表示，通过关系组合传播更新实体和关系，再沿用本项目的 ConvE 风格打分器。训练目标包含原有三元组 BCE、可选 BPR 排序；`in_kppd` 额外启用全局流行度、个人流行度/需求分支和辅助约束，旧公平正则在此实验中关闭。一次训练批次内，BCE、BPR、KPPD 等打分共享同一次传播结果，使 dropout 图表示一致，并避免重复传播整图；下一批次重新计算。
3. **全测试集推荐**：测试入口按检查点配置还原骨干和图，导出每位测试学生的习题分数。KPPD 实验保留原分数和去偏分数；后处理实验再用 `fairness_rerank.py` 产生重排分数。检查点记录 CompGCN 版本、层数、算子、dropout 和消息图哈希，旧原型检查点不能混用。
4. **评价**：`evaluate_recommendations.py` 对同一完整测试学生集合计算 Ada、正式 NOV、Ep 和公平性指标。正式 `NOV` 是 **KG4Ex-NOV-Set**：将每位学生 Top-N 习题的知识点取并集，和该学生历史答对知识点计算一次 Jaccard 新颖性，再对测试学生取平均；单题平均版和旧时间加权 NOV 仍作为附加记录。评价要求推荐分数覆盖完整测试学生集合，因此 `--max-test-users` 只能用于推理调试，不能用于正式评价。
5. **编排与汇总**：`run_v3_kppd_pipeline.py` 执行 Pre/In/Post 八组组合，其中四个带 Post 的组复用对应无 Post 组的检查点分数，仅重排并重新评价。`run_v3_ablation_and_comparison.py` 在其外层组织八个对比模型、非 KPPD 四组、KPPD 四组，以及独立批次的无 CompGCN 第九组。分阶段执行时从同一批次下所有已完成的评价目录重建汇总 CSV，以保留先前阶段的行。`--dry-run` 只打印计划，不标记训练/评价完成。

主要结果目录是 `Code/runs/<dataset>/<dataset>_<batch-id>_v3/<实验名>/seed<种子>/`；无 CompGCN 对照使用 `<batch-id>_v3_no_compgcn`。统一表格及状态在 `Code/runs/<batch-id>/`。对比模型位于 `Code/runs/<dataset>/<dataset>_<batch-id>_comparison/`。每个正式运行要使用新的批次名，避免旧检查点和架构配置混用。

## 4. 与 CompGCN 论文及作者源码的关系

核对来源：Vashishth 等人的 *Composition-based Multi-Relational Graph Convolutional Networks*（本项目 `参考论文/1911.03082v2.pdf`）、[官方仓库](https://github.com/malllabiisc/CompGCN)、[官方传播层](https://github.com/malllabiisc/CompGCN/blob/master/model/compgcn_conv.py)、[官方模型和 ConvE 解码器](https://github.com/malllabiisc/CompGCN/blob/master/model/models.py)。官方仓库采用旧版 PyTorch/PyG API；本项目用当前 PyTorch 张量实现核心计算，未直接复制其整套训练程序。

| 核对点 | 官方实现 | 当前实现与融合判断 |
| --- | --- | --- |
| 消息组合 | `corr`/`sub`/`mult` | 三种算子均可选，默认 `corr`；循环相关采用等价的现代 `torch.fft` 写法。 |
| 传播方向 | 正向、逆向、自环分别变换，三路聚合 | 保留三路权重、可学习自环关系、三路均分、dropout、BatchNorm、tanh。 |
| 关系更新与解码 | 每层更新关系，最后进入 ConvE 打分 | 保留关系更新；与既有语义关系向量叠加后进入本项目原打分器，保持推荐与 KPPD 接口。`rec` 不进消息边，但作为可学习查询关系参与更新和解码。 |
| 边强度 | 离散关系边 | 将 `[0,1]` 的掌握/遗忘强度编码并加到关系表示，这是本项目扩展，尚需消融证明有效。 |
| 归一化 | 每个方向使用同一节点度向量 | 对单向二部子图使用源出度和目标入度；否则只有入边的目标节点可能得不到消息。这是有意偏离，不能声称与官方逐项数值相同。 |
| 实体初始表示 | 可学习实体嵌入 | 保留旧模型的学生/习题语义特征编码并加入关系传播；为适配教育图与现有消融，不是直接照搬论文的实体输入。 |

当前默认一层传播只能覆盖一跳邻居；学生→知识点→习题的完整两跳传递需要两层。代码支持 `--compgcn-layers 2` 且 XES 已完成单批次检查，但一层或两层哪个更好，必须由完整对照实验决定。当前也没有与官方旧环境做逐值同输入数值对等测试；现有证据是公式/源码级核对、单元测试与项目流程连通性，不能称为官方模型的完全复刻。

## 5. 会做哪些实验和对比

### 5.1 九组主消融（统一入口默认运行）

| 类别 | 实验名 | 做法 |
| --- | --- | --- |
| 无 Pre/In/Post | `baseline` | CompGCN → ConvE 基线。 |
| 仅 Pre | `pre_item_kc` | 调整习题和知识点的推荐训练边。 |
| 仅 In | `in_kppd` | KPPD 去偏训练及推理打分。 |
| Pre+In | `pre_in_kppd` | 同时启用 Pre 和 KPPD。 |
| 仅 Post | `post_only` | 重排 `baseline` 的分数。 |
| Pre+Post | `pre_item_kc_post` | 重排 `pre_item_kc` 的分数。 |
| In+Post | `in_kppd_post` | 重排 `in_kppd` 的去偏分数。 |
| 完整主方法 | `pre_in_kppd_post` | 重排 `pre_in_kppd` 的去偏分数。 |
| 去 CompGCN | `no_compgcn` | 保留 Pre+KPPD+Post 与 ConvE 打分器，仅删除 CompGCN 图编码层。 |

另外，旧的 `run_semantic_experiments.py` 还可单独执行七个语义消融：主模型、只用 ID、去掉关系/学生特征/习题特征/掌握度/遗忘度；这些**不在当前统一入口默认的九组主消融中**。该旧编排器目前没有透传 `--backbone`，默认跑 ConvE。若要得到 CompGCN 版本的七项组件消融，还需扩展这一入口，并重新核查“去掉掌握/遗忘”时消息图也同步删除相应关系；目前不能把旧结果当作 CompGCN 消融。

### 5.2 外部对比模型（统一入口默认全部运行）

默认顺序：`EB-CF`、`SB-CF`、`CBF`、`TransE`、`TransE-adv`、`RotatE`、`DistMult`、`ComplEx`。前三个是推荐基线，后五个是知识图谱嵌入基线。它们与主模型使用选中的相同正式数据及评价定义，但各自训练程序保持原实现；`--backbone compgcn` 仅切换 V3 主模型，不改变这八个模型。正式计划的随机种子为 `2024,2025,2026`，Top-N 为 `5,10,…,50`。

### 5.3 为验证 CompGCN 升级还需要的对照

第九组在完整 Pre+KPPD+Post 下比较“语义表示 → ConvE”与“语义表示 → CompGCN → ConvE”；ConvE 解码器两组均保留。随后可补做一层/两层和 `corr/sub/mult` 的敏感性实验。连续边强度消融与官方实现的严格数值对等尚未形成正式实验，现阶段只可列为后续验证项。正式三种子、完整轮次尚未运行，不能根据冒烟检查判断优劣。

## 6. 已做的流程检查与复现入口

- 三套最终消息图均能从各自 ER 图重新构造，关键数组完全一致。
- 聚焦单元测试共 33 项通过，覆盖算子/关系梯度、批次传播缓存、运行命令、分阶段状态保留与汇总，以及最终图派生消融的正式指标识别。
- Algebra2005 的 144 位测试学生分数能完整导出，并生成 Ada、NOV、Ep 与公平性文件；统一 V3 下 `baseline`、`in_kppd`、`pre_item`、`post_only` 的训练、推理、评价与汇总均完成一批次冒烟检查。
- Eedi、XES 的一层，以及 XES 的两层 CompGCN 均完成 GPU 单批次反向传播。这里没有执行多轮训练或三种子效果比较。
- 2026-10-16 新九组入口在 Algebra2005、种子 2024 上完成单轮单批次端到端检查：统一表共 9 个方法 × 10 个 Top-N 值 = 90 行；四个 Post 组均没有独立训练文件，且运行状态记录了对应父实验的来源分数；第九组的检查点配置确认使用 `conve`。主方法与第九组所派生的 Pre 图中 `triples.txt` 和 `educational_kg_v2.npz` 的 SHA-256 各自相同，确认此对照使用同一训练图。相关 32 项单元测试通过。这一检查只验证流程，不能据其指标判断模型优劣。
