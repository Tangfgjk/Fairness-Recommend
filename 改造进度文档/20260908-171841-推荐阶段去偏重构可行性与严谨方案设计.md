# 推荐阶段去偏重构可行性与严谨方案设计

生成时间：2026-09-08 17:18:41

## 1. 核心结论

可以在推荐阶段做去偏，而且与现有 2CKG4ER 的任务位置一致。相比把习题与知识点的均衡曝光笼统称为“公平性”，将研究问题收敛为“教育推荐中的流行度偏差及偏差放大缓解”更容易定义、测量和论证。

但是，不能只把 `fairness` 改名为 `debias`。当前实现还需要完成四个关键转换：

1. 从“曝光越均匀越好”改为“模型不应无理由地放大训练数据中的流行度，同时应保留学生学习需求与习题相关性”。
2. 从只看输出 Gini、Coverage 和长尾占比，改为同时比较输入分布、伪标签分布和模型输出分布，直接测量偏差放大。
3. 统一使用真实训练交互定义习题和知识点流行度，不能再默认使用模型前置生成的 `rec` 边定义偏差。
4. 将因果主张限制在证据允许的范围内。Eedi 当前没有随机曝光日志或可靠的展示概率，因此可以严谨地声称“流行度去偏”“偏差放大缓解”或“因果启发的去偏”，暂时不能声称已经无偏估计真实兴趣或消除了曝光因果偏差。

建议的新论文任务名称为：

> **面向教育资源流行度偏差的知识感知可解释习题推荐**

英文可写为：

> **Knowledge-aware Popularity Debiasing for Explainable Exercise Recommendation**

## 2. 上游去偏与推荐去偏的关系

老师提供的 DBCD 论文处理的是上游认知诊断中的 MNAR 问题：学生只回答了一部分习题，而且被观测到的回答不是随机样本，导致知识状态估计偏差。认知诊断结果又会作为习题推荐和学习路径规划的输入，因此上游偏差可能向下游传播。

当前 2CKG4ER 处理的是下游推荐：根据学生掌握度、遗忘状态和知识结构，为学生排序习题。推荐阶段同样可能产生偏差，主要表现为热门习题或热门知识点被反复推荐，模型输出比训练数据更加集中。

两者不是同一个任务：

| 层次 | 输入偏差 | 直接影响 | 对应方法 |
|---|---|---|---|
| 认知诊断去偏 | 学生作答记录 MNAR、自选择、题目暴露不均 | 掌握度估计失真 | DBCD、CVIB、IPS/DR 类方法 |
| 推荐去偏 | 交互流行度、伪推荐标签偏斜、模型偏差放大 | 推荐列表过度集中于热门习题/知识点 | MACR、DICE、PDA、DecRS、谱正则、重排序 |

因此，本项目可以先独立研究推荐阶段去偏。后续若加入 DBCD 类认知诊断模型，可以形成“上游诊断去偏 + 下游推荐去偏”的完整链路，但不应在本阶段混为一个贡献。

## 3. 当前数据能支持哪些偏差定义

### 3.1 可以直接验证的偏差

#### 习题流行度偏差

真实训练交互中，不同习题被不同学生作答的频次差异很大。推荐模型如果把这种频次当成相关性，可能过度推荐高频习题。

建议定义习题流行度：

```text
pop_item(i) = 训练集中与习题 i 发生交互的唯一学生数
```

唯一学生数比总交互次数更不容易被个别学生的重复作答支配，同时保留 `interaction_count` 作为敏感性定义。

#### 知识点流行度偏差

知识点流行度不是独立观测，而是通过 Q 矩阵从习题交互聚合得到：

```text
pop_kc(c) = Σ_i pop_item(i) * Q[i,c] / max(1, Σ_c Q[i,c])
```

它更准确的含义是“知识内容在训练交互中的出现频率”。论文中应称为知识内容流行度偏差或知识机会集中，而不是直接称为对知识点的权利公平。

#### 偏差放大

若模型输出比训练交互或训练伪标签更集中于热门资源，则存在偏差放大。该定义与 DecRS 和谱视角研究一致，也比“Gini 高就是不公平”更严谨。

### 3.2 当前不能直接验证的偏差

当前 Eedi 数据和流水线无法可靠识别以下机制：

- 曝光偏差：缺少“平台展示了哪些题但学生没有点击/作答”的日志。
- 位置偏差：缺少推荐位置与点击日志。
- 从众偏差：缺少可区分“真实学习需要”和“因为热门而选择”的干预数据。
- 真实反事实兴趣：没有随机曝光或可验证的倾向分数，无法知道未作答习题如果被展示后是否会被选择。

这些机制可以作为理论动机或未来工作，但不能仅凭交互频次宣称已经被因果识别。

## 4. 当前代码中的偏差链条

### 4.1 原始训练交互

学生作答数据本身是选择性观测，具有长尾分布。这是上游数据偏差来源。

### 4.2 前置伪推荐标签

`Code/front_pipeline/build_er_graph.py` 不是从真实推荐点击构造 `rec` 正边，而是计算教育距离：

```text
d(u,i) = sqrt((delta_1 - mastery_product(u,i))^2
            + (delta_2 - forgetting(u,i))^2)
```

然后为每个训练学生选择距离最小的 Top-10 习题，写成 `uid rec ex`。因此：

- `rec` 边是启发式伪标签，不是真实的用户偏好标签。
- 每个学生固定 10 条边，改变的是习题分布而不是用户边数。
- 偏差既可能来自真实交互，也可能由掌握度、遗忘度、Q 矩阵覆盖和固定 Top-10 规则共同引入。

### 4.3 2CKG4ER 模型学习

ConvE 对知识图谱中的 `rec` 边进行链接预测。如果高频习题在伪标签图中出现更多，参数更新会更频繁，模型可能进一步放大热门习题得分。

### 4.4 输出排序

模型对每个学生的全部习题打分并产生 Top-K。当前后处理使用长尾奖励、知识点奖励和累计曝光惩罚，可以改变结果分布，但累计全局曝光会受到用户遍历顺序影响。

完整偏差链应写成：

```text
真实训练交互分布 p_data
    -> Top-10 伪标签分布 p_label
    -> 基础模型输出分布 p_base
    -> 去偏模型输出分布 p_debias
```

论文需要分别比较这四个分布，而不是只比较 `p_base` 和 `p_debias`。

## 5. 现有 Pre/In/Post 能否保留

可以保留组合式架构，但必须重新定位。

| 现有阶段 | 当前行为 | 去偏后的准确定位 | 是否作为主方法 |
|---|---|---|---|
| Pre | 在教育 Top-M 候选中按逆流行度重构 10 条 `rec` 边 | 流行度感知伪标签重构 | 可作为数据级基线或组件 |
| In | 令模型软曝光接近平滑流行度目标 | 分布正则化训练 | 可保留，但应改成学生条件目标 |
| Post-soft | 原始分数加长尾/KC 奖励并减累计曝光惩罚 | 流行度感知软重排序 | 作为强后处理基线 |
| Post-quota | 强制长尾和 KC 覆盖比例 | 约束式重排序 | 作为上界/干预强度基线，不宜作为唯一主方法 |

建议内部暂时保留旧参数名以兼容已有脚本，新增论文层名称：

- `popularity_debias_pre`
- `popularity_regularized_training`
- `popularity_debias_rerank`

现有模块不是严格的因果去偏：Pre 会构造新的伪标签，In 是分布匹配，Post 是排序干预。论文应如实描述。

## 6. 推荐阶段去偏的严谨问题定义

设学生集合为 U，习题集合为 I，知识点集合为 C，Q 矩阵为 `Q[i,c]`。

- `r(u,i)`：2CKG4ER 给出的教育相关性分数。
- `p_i`：习题在真实训练交互中的流行度。
- `p_c`：由 Q 矩阵聚合的知识点流行度。
- `need(u,c)`：学生对知识点 c 的学习需要，可由低掌握度、高遗忘度和课程约束构成。
- `x(u,i)`：习题 i 对学生 u 的知识需求匹配度。

本项目不追求全局均匀曝光，而是学习一个教育相关性条件下的去偏目标：

```text
q_u(i) ∝ exp(r(u,i) / T_r)
         * (p_i + ε)^(-lambda_pop)
         * exp(lambda_need * x(u,i))
```

其中：

- `lambda_pop=0` 时退化为相关性排序。
- `lambda_pop` 增大时抑制无理由的热门倾向。
- `lambda_need` 防止为了长尾而推荐学生不需要的知识点。
- 目标是形成效用与去偏的 Pareto 前沿，而不是寻找对所有数据集都相同的固定参数。

## 7. 必须新增的诊断和指标

### 7.1 输入与输出分布

需要分别保存：

- `train_item_popularity`
- `pseudo_label_item_popularity`
- `baseline_item_exposure@K`
- `debiased_item_exposure@K`
- 对应的 KC 分布

### 7.2 偏差放大指标

#### Gini 放大量

```text
DeltaGini_item@K = Gini(p_model@K) - Gini(p_reference)
DeltaGini_kc@K   = Gini(p_model_kc@K) - Gini(p_reference_kc)
```

`p_reference` 至少报告真实训练交互和伪标签两种参照。

#### 分布偏移

对归一化后的分布计算：

```text
JS_item@K = JS(p_model@K || p_reference)
JS_kc@K   = JS(p_model_kc@K || p_reference_kc)
```

JS 距离比只看 Gini 更能判断模型是否改变了具体资源分配。

#### Average Recommendation Popularity

```text
ARP_u@K = (1/K) * Σ_{i in TopK(u)} log(1 + pop_item(i))
ARP@K   = mean_u ARP_u@K
```

ARP 越高表示列表越偏向热门习题，但不能单独判断推荐质量。

#### Popularity Lift

```text
PL_u@K = (ARP_u@K - ProfilePop_u) / (ProfilePop_u + ε)
```

`ProfilePop_u` 是学生训练历史的平均习题流行度。该指标回答：系统是否把学生推向比其历史偏好更热门的内容。应报告全体均值，并按低、中、高流行度偏好学生分组。

#### Head/Mid/Tail 指标

在固定的真实训练交互定义下报告：

- Head/Mid/Tail Exposure Share@K
- Head/Mid/Tail Item Coverage@K
- 若存在有效测试相关性标签，再报告 Head/Mid/Tail Recall@K 和 NDCG@K

### 7.3 现有指标的保留方式

`ItemExposureGini`、`KCExposureGini`、Coverage、LongTailShare 仍然有用，但应归入“资源分布与偏差诊断指标”，不再单独称为公平性证明。

Ada 和 NOV 继续保留。Ada 反映教育适配，NOV 反映新颖性，但它们不能替代标准 Top-K 相关性评价。

## 8. 推荐的主方法路线

### 8.1 第一层：先把现有方法改成可信的去偏基线

优先级 P0：

1. 所有脚本默认使用 `train_interactions + unique_users` 定义流行度。
2. 评价时固定同一份流行度上下文，不因 Pre 后图不同而改变长尾集合。
3. 新增 `p_data -> p_label -> p_base -> p_debias` 偏差放大报告。
4. 后处理加入用户顺序置换实验，或改为每用户独立的流行度校正，避免结果依赖遍历顺序。
5. 明确区分伪标签重构与真实交互重加权。

### 8.2 第二层：模型内主方法采用反事实流行度分支

建议优先实现一个 MACR/PPAC 启发、适配 2CKG4ER 的轻量主方法：

```text
s_total(u,i) = F(s_edu(u,i), s_pop_global(i), s_pop_personal(u,i), s_kc(u,i))
```

其中：

- `s_edu` 由现有学生、习题、知识图谱关系和教育状态产生。
- `s_pop_global` 只接收真实训练流行度特征。
- `s_pop_personal` 表示与学生历史流行度偏好的匹配，避免把所有学生都推向同一个长尾目标。
- `s_kc` 表示学生知识需求与习题知识点的匹配。

训练时同时学习主推荐任务与辅助流行度分支；推理时通过反事实消融或减去受控的流行度直接效应得到 `s_debias`。这比直接要求所有学生的模型曝光接近一个全局分布更符合个性化推荐。

注意：实现应表述为“MACR/PPAC 启发的反事实分数校正”。除非给出可识别的结构因果模型、干预变量和假设验证，不应直接声称恢复了真实因果兴趣。

### 8.3 第三层：知识感知的对比去偏增强

在主方法稳定后，可加入 CORE 和 CounterCLR 启发的双视图：

1. 事实图：原始训练图。
2. 流行度衰减图：对热门 `rec` 或交互边以更高概率降权/删除，但保留每个学生的基本连接。
3. 共享编码器分别学习两种图表示。
4. 对同一学生、习题和知识点表示做对比一致性约束。
5. 推荐损失保证相关性，对比损失鼓励表示对流行度扰动稳定。

对当前项目，知识点不能只是被平均计数。图增强应保护：

- 学生薄弱知识点对应边；
- 先修知识关系；
- 每个学生至少一个有效候选；
- 每个被保留习题的 Q 矩阵语义。

这一路线可称为“因果启发的流行度反事实图增强”，而不是声称真实生成了未观测反事实。

### 8.4 暂不作为主线的 IPS/SNIPS/DR

IPS、SNIPS 和 Doubly Robust 在有曝光倾向或随机日志时理论最强。但是当前数据没有可靠的展示事件和倾向概率。仅用习题频次倒数冒充 propensity 会混淆“热门程度”和“被展示概率”。

因此：

- 可把频次重加权作为 heuristic baseline。
- 不应称其为无偏 IPS，除非后续能获得曝光日志、随机测试集或建立并验证 propensity 模型。
- Hoiles 和 Schnabel 等工作可作为为什么未来需要 off-policy 评价的理论依据。

## 9. 实验设计

### 9.1 E0：偏差链诊断

不训练新模型，先回答：

1. 真实训练交互是否长尾？
2. Top-10 伪标签是否放大或减弱了长尾？
3. 2CKG4ER 是否进一步放大热门习题和热门 KC？
4. 放大主要发生在 Item 还是 KC？

输出 Top-10/20/50 的 Gini、ARP、JS、Coverage、Head/Mid/Tail Share 和 DeltaGini。

### 9.2 E1：现有阶段基线

统一数据和评价协议后运行：

- Base 2CKG4ER
- Pre only
- In only
- Post-soft only
- Post-quota only
- Pre+In
- In+Post
- Pre+In+Post

该组用于说明每个干预位置的能力和代价，不把组合自动当成最佳方法。

### 9.3 E2：新模型对比

建议对比：

- Base 2CKG4ER
- 频次逆权重训练
- 现有分布正则 In
- MACR 风格反事实分支
- 个体流行度增强的 PPAC 风格分支
- 知识感知反事实分支
- 知识感知反事实分支 + Post-soft
- 可选：反事实图对比增强

### 9.4 E3：消融实验

- 去掉 global popularity branch
- 去掉 personal popularity branch
- 去掉 KC need conditioning
- 去掉 counterfactual inference，仅保留多任务训练
- 去掉对比学习
- 事实图与随机删边图对比
- 事实图与流行度衰减图对比

### 9.5 E4：参数与鲁棒性

- 流行度抑制强度：`0, 0.05, 0.1, 0.2, 0.5, 1.0`
- KC 需求权重：`0, 0.1, 0.3, 0.5`
- 反事实图热门边衰减率：`0.1, 0.3, 0.5, 0.7`
- Item/KC 长尾阈值定义敏感性
- 后处理用户顺序至少 10 次随机置换
- 筛选阶段单 seed，最终主表至少 3 个 seed，并报告均值、标准差和显著性

### 9.6 评价协议

最终论文表格应分四组：

| 维度 | 指标 |
|---|---|
| 教育效用 | Ada@K、NOV@K、知识需求匹配度 |
| 排序效用 | Recall@K、NDCG@K、HR@K，前提是建立有效的留出相关性标签 |
| 去偏效果 | ARP、Popularity Lift、DeltaGini、JS、Head/Mid/Tail Exposure/Coverage |
| 稳健性 | 多 seed、用户顺序、长尾阈值、流行度分布漂移 |

如果暂时不能建立有效的 held-out 推荐标签，论文必须把任务表述为“教育适配排序与资源流行度去偏”，不能仅凭 Ada/NOV 和分布指标宣称提升了传统推荐准确率。

## 10. 实施优先级

### P0：论文成立前必须完成

1. 统一真实训练交互流行度来源。
2. 固定 Item/KC head-tail 划分和 Q 矩阵版本。
3. 增加输入到输出的偏差放大指标。
4. 将“公平性”结果表改为“流行度偏差与资源分布”结果表。
5. 明确 `rec` 边为伪标签，补充 `p_data/p_label/p_model` 诊断。
6. 检查测试候选集和训练已见习题过滤，避免评价泄漏或协议不一致。

### P1：主方法改造

1. 实现 global/personal popularity 辅助分支。
2. 实现反事实推理分数校正。
3. 将 KC 学习需求作为条件，而不是强迫全局 KC 均匀。
4. 保留 Pre/In/Post 自由组合和独立消融。
5. 对后处理做用户顺序鲁棒性实验。

### P2：增强与论文扩展

1. 流行度衰减反事实图。
2. 学生/习题/KC 对比一致性损失。
3. 多数据集迁移和参数归一化。
4. 如获得曝光日志，再加入 IPS/SNIPS/DR 和 off-policy 评价。

## 11. 建议的开发顺序

1. 新建开发分支 `v3-recommendation-debiasing`。
2. 先实现 `recommendation_bias_context.py` 和 `recommendation_bias_metrics.py`，不改变模型。
3. 生成 E0 偏差链报告，确认问题真实存在且基线确有放大。
4. 把现有 Pre/In/Post 接到统一偏差上下文，复跑现有结果。
5. 实现反事实流行度分支，先做小规模正确性测试。
6. 完成单 seed 筛选，再运行多 seed 主实验。
7. 只有当反事实分支有效后，再加入双图对比模块。

这一步序很重要：如果 E0 没有证明 2CKG4ER 放大了输入偏差，就不能把“缓解偏差放大”作为主问题；如果只证明输出集中，则论文应降级表述为“流行度感知的资源分布校正”。

## 12. 可采用与不可采用的论文表述

推荐使用：

- 缓解教育推荐中的习题流行度偏差。
- 减少模型相对训练数据的流行度偏差放大。
- 在保持教育适配性的同时提升长尾资源可见性。
- 知识感知、因果启发的反事实流行度校正。

当前不建议使用：

- 实现了公平推荐。
- 恢复了学生真实兴趣。
- 消除了曝光偏差。
- 获得了无偏推荐结果。
- 使用了严格的反事实标签。

## 13. 文献依据概览

| 年份 | 工作 | 对本项目的直接启示 |
|---|---|---|
| 2016 | Recommendations as Treatments | 选择性观测会同时污染训练与评价，IPS 需要 propensity 假设 |
| 2016 | Bounded Off-Policy Evaluation for Course Recommendation | 教育推荐也可采用反事实/off-policy 评价，但需要日志策略信息 |
| 2019 | Doubly Robust Joint Learning | MNAR 推荐可结合 outcome 与 propensity，但依赖可识别假设 |
| 2019 | The Unfairness of Popularity Bias | 流行度影响不同用户群体，不能只追求全局长尾占比 |
| 2020/2021 | MACR | 可建模流行度直接效应，并在推理时进行反事实校正 |
| 2021 | DICE | 可拆分兴趣与从众原因，但当前项目缺少从众真值，应谨慎命名 |
| 2021 | PDA | 训练去混杂与推理时受控利用流行度可以分开设计 |
| 2021 | DecRS | 应测量模型是否放大输入不平衡，而不是把输入分布本身等同于模型错误 |
| 2021 | AutoDebias | 去偏参数可数据驱动学习，但需要可信的无偏/验证信号 |
| 2023 | Exposure-to-Interaction Popularity Debiasing | 只增加长尾曝光不必然增加有效交互，教育相关性必须作为约束 |
| 2023/2024 | CounterCLR | 可通过 MNAR 反事实视图和对比学习增强稳健表示 |
| 2024/2025 | Spectral Popularity Bias Amplification | 模型谱结构可记忆并放大流行度，提供新的模型内正则基线 |
| 2024 | PPAC | 全局流行度不足，应考虑学生个体流行度偏好 |
| 2024 | Identifiability Matters | 无偏学习并非仅靠损失名称成立，必须说明可恢复条件和不可识别边界 |
| 2026 | CORE | 教育推荐可用热门边衰减的反事实图和对比学习，但仍需审慎区分因果识别与因果启发 |
| 2026 | DBCD | 上游认知诊断 MNAR 去偏可改善推荐输入，但与下游推荐去偏是互补任务 |
