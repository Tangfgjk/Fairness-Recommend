# quota_strict 公平性重排实现记录

## 1. 实现目标

本次在离线后处理模块 `fairness_rerank.py` 中新增 `quota_strict` 方法，用于尝试强约束公平性重排。

该方法不重新训练模型，只读取基础模型输出的 `uid_ex_scores.pkl`，在候选池中重排每个学生的推荐列表。

核心目标：

- Top-K 前缀中至少包含一定数量长尾习题。
- Top-K 前缀中至少覆盖一定数量知识点。
- 满足 quota 后，剩余位置尽量保持原 2CKG4ER 分数排序。

## 3. 新增方法

新增方法：

```text
--method quota_strict
```

新增参数：

```text
--quota-top-k
--min-long-tail-items
--min-kc-coverage
--head-ratio
--long-tail-ratio
```

默认值：

```text
quota_top_k = 10
min_long_tail_items = 1
min_kc_coverage = 10
head_ratio = 0.2
long_tail_ratio = 0.8
```

## 4. 算法流程

对每个学生：

1. 从原始 2CKG4ER 分数中取候选池，例如原始 Top-150。
2. 根据训练集 `triples.txt` 中的习题流行度划分长尾习题。
3. 在候选池中构造 quota 前缀，例如 Top-10。
4. 阶段 A：优先选入原模型分数较高、能带来新知识点的长尾习题，直到满足 `min_long_tail_items`。
5. 阶段 B：继续选择能带来最多新知识点的习题，直到满足 `min_kc_coverage`。
6. 阶段 C：quota 前缀剩余位置以及后续 Top-K 位置，按原模型分数补齐。
7. 输出 rank-only score 文件，供现有 `evaluate_recommendations.py` 继续评估。

## 5. 可行性处理

该方法是 strict，但不会从候选池外强行拉入习题。

如果候选池中没有足够长尾习题：

```text
实际长尾 quota = min(要求长尾数, 候选池中可用长尾数, quota_top_k)
```

如果候选池中无法覆盖目标知识点数：

```text
实际 KC quota = min(要求 KC 数, 候选池可覆盖 KC 数)
```

因此它是候选池内的严格约束，不会牺牲到完全脱离原模型相关性。

## 6. 元数据输出

`quota_strict` 会额外输出：

```text
quota_satisfied_users
quota_satisfied_user_ratio
average_quota_long_tail_items
average_quota_kc_coverage
average_effective_quota_long_tail_target
average_effective_quota_kc_target
long_tail_item_count
```

用于检查 quota 是否真的生效。

其中 `average_effective_*_target` 表示候选池内实际可满足的 quota 目标。如果某个学生候选池中没有足够长尾题或无法覆盖足够知识点，统计时会按可行目标判断，而不是把不可行 quota 记为失败。
