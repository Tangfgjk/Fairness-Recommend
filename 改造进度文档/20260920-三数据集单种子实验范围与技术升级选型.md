# 三数据集单种子实验范围与技术升级选型

日期：2026-09-20

## 1. 本阶段实验范围调整

后续实验范围收敛为三个数据集：

| 数据集 | 定位 | 继续保留原因 |
|---|---|---|
| `Eedi` | 主分析数据集 | 前期实验、E0 完整偏差链和 Eedi 汇报材料最充分，适合作为方法开发与案例解释主数据集。 |
| `algebra2005` | 中等规模验证数据集 | 已完成完整 E1 消融，且 E0 有 `p_data/p_label/p_base/p_debias`，适合验证方法是否跨数据集有效。 |
| `XES3G5M-sub-small` | 大规模压力验证数据集 | 规模更大，流行度偏差更明显，适合检查方法在更大教育数据上的稳定性与运行成本。 |

暂时不再继续扩展 `assist2009-sub` 和 `statics2011` 的完整实验。原因是当前目标已经从“尽可能多数据集覆盖”转为“围绕去偏主方法做技术升级”，过多数据集会拖慢迭代，且当前只需证明方法在小、中、大三类数据上都有趋势即可。

随机种子暂定只跑一个：

```text
seed = 2024
```

当前阶段单 seed 的目的不是形成最终显著性结论，而是快速筛选技术路线。待主方法稳定后，再决定是否对最终主表补三 seed 或五 seed。

## 2. 当前任务定位

现阶段不要把目标写成“学生侧公平已经完成”，也不要把目标写成“题目/KC 天然公平”。更稳妥的任务定位仍然是：

> 面向学生学习机会的教育资源流行度去偏。当前先从资源侧偏差链和模型去偏做起，学生侧学习机会公平作为最终验证阶段。

也就是说，下一步技术升级应优先回答：

1. 当前模型是否放大了真实训练交互中的热门资源偏差？
2. 新方法能否减少 `p_base -> p_debias` 的偏差放大？
3. 新方法是否比现有 Pre/In/Post 中的全局曝光正则更合理？
4. 去偏后 Ada/NOV 是否没有明显崩坏？
5. 资源去偏是否为后续学生侧学习机会公平提供更好的中间机制？

## 3. 技术升级结论

当前最适合优先替换的不是整个推荐主干，而是模型内去偏模块。

建议将当前 `in_only` 使用的“全局 expected exposure regularizer”升级为：

> **知识需求约束的个体流行度反事实去偏模块**

英文可暂定为：

> **Knowledge-aware Personal Popularity Counterfactual Debiasing**

核心思想是引入三个分支：

```text
s_main(u, i)          原 2CKG4ER 教育推荐主分数
s_global_pop(i)       习题全局流行度效应
s_personal_pop(u, i)  学生个人流行度偏好效应
s_need(u, i)          学生知识需求匹配效应
```

推理时使用反事实分数校正：

```text
s_debias(u, i)
  = s_main(u, i)
    - λ_g * s_global_pop(i)
    - λ_p * s_personal_pop(u, i)
    + λ_k * s_need(u, i)
```

其中：

- `s_global_pop(i)` 用真实训练交互中的习题流行度建模，捕捉全局热门效应。
- `s_personal_pop(u, i)` 建模学生是否本来就偏向热门或长尾资源，避免把所有学生强行推向同一种长尾比例。
- `s_need(u, i)` 用学生掌握度、遗忘状态和习题 Q 矩阵约束教育相关性，防止为了去热门而推荐不适合的题。

这一步比直接替换主干更适合当前项目，因为它直接对应现有问题链：

```text
p_data -> p_label -> p_base -> p_debias
```

并且能在 E0 诊断中自然产生：

```text
p_base_raw
p_base_corrected
p_debias
```

从而证明“模型是否放大偏差”以及“反事实去偏是否缓解放大”。

## 4. 为什么不建议第一步直接换成 LLM、KT 或复杂 Transformer

| 候选技术 | 是否适合作为当前第一步 | 原因 |
|---|---|---|
| LLM 推荐 | 否 | 当前任务核心是流行度偏差链和可控去偏，LLM 会引入语义增强与生成能力，问题过大且难以解释偏差变化。 |
| KT 主模型 | 暂不优先 | KT 更适合最终学生状态建模和学习机会公平，当前还处于资源去偏主方法阶段。 |
| KGTN/Graph Transformer | 暂不优先 | 技术成本高，容易把“主干能力提升”和“去偏有效性”混在一起。 |
| IPS/DR | 暂不优先 | 当前数据缺少真实曝光日志和可靠 propensity，不能严谨声称无偏估计。 |
| 直接全局均匀曝光正则 | 不宜作为主方法 | 它可以作为 baseline，但没有考虑学生个人偏好和教育需求，容易被质疑“为了长尾而长尾”。 |

## 5. 主干是否需要换

主干可以后续从 ConvE 升级为 CompGCN，但不建议把它作为第一优先。

推荐顺序是：

1. 保留当前 ConvE/2CKG4ER，先实现反事实流行度去偏分支。
2. 加入 BPR 或 BCE+BPR 排序损失，让训练目标更接近 Top-K 推荐。
3. 加入 popularity-aware negative sampling，特别是 popular negative 和 mixed negative。
4. 在上述方法稳定后，再将 backbone 从 ConvE 扩展为 CompGCN。

如果必须选择一个“主干替换技术”，最推荐的是：

> **CompGCN**

原因是 CompGCN 面向多关系图，能同时更新实体和关系表示，和当前 `student/exercise/KC/relation/triples.txt` 格式最兼容。它可以保留 `score_triples_logits` 和 `score_tails_logits` 接口，减少对评价、rerank、E0 诊断脚本的破坏。

但论文主贡献不应只写“把 ConvE 换成 CompGCN”。更合理的表述是：

> 在知识图谱教育推荐主干上，引入个体流行度反事实分支与知识需求约束，缓解模型对热门资源的偏差放大。

## 6. 推荐的 E2 技术升级实验矩阵

本阶段只在 `Eedi`、`algebra2005`、`XES3G5M-sub-small` 上跑，先只跑 `seed=2024`。

| 编号 | 方法 | 目的 |
|---|---|---|
| E2-B0 | ConvE/2CKG4ER + BCE | 固定当前 baseline。 |
| E2-B1 | ConvE/2CKG4ER + BPR | 验证排序损失是否改善 Top-K 推荐。 |
| E2-B2 | ConvE/2CKG4ER + BCE+BPR | 验证混合目标是否更稳定。 |
| E2-N1 | BCE+BPR + popular negative | 验证热门负样本是否减少模型对热门题的无理由偏好。 |
| E2-D1 | B0 + global popularity branch | 检查仅建模全局流行度是否有效。 |
| E2-D2 | B0 + global + personal popularity branch | 检查个人流行度偏好是否必要。 |
| E2-D3 | B0 + global + personal + KC need branch | 作为当前阶段主方法候选。 |
| E2-D4 | D3 + post rerank | 检查模型内去偏与后处理是否互补。 |
| E2-G1 | CompGCN + BCE+BPR | 后续主干升级候选，不作为第一轮必要项。 |

第一轮建议只跑：

```text
E2-B0, E2-B2, E2-D1, E2-D2, E2-D3
```

如果 D3 在三数据集上表现稳定，再跑 D4 和 G1。

## 7. 评价协议

继续沿用当前已经统一的真实训练交互口径：

```text
popularity_source = train_interactions
popularity_aggregation = unique_users
```

每个方法至少输出：

| 维度 | 指标 |
|---|---|
| 教育效用 | Ada@10/20/50/100、NOV@10/20/50/100 |
| 资源去偏 | ItemGini、KCGini、ItemCoverage、KCCoverage、LongTailShare |
| 偏差链 | Gini、JS、ARP、Head/Mid/Tail exposure |
| 放大诊断 | `p_data -> p_label -> p_base -> p_debias` |
| 稳定性 | 三数据集一致性，先不做多 seed |

后续文档和表格中应避免把 Item/KC Gini 单独称为“公平性已经提升”。推荐写法是：

```text
资源曝光集中度降低
热门资源偏差放大得到缓解
长尾教育资源可见性提升
在教育相关性约束下改善资源分布
```

## 10. 最终建议

当前最合适的技术升级路线不是一次性把模型换成复杂新主干，而是：

```text
ConvE/2CKG4ER
  -> BCE+BPR 排序目标
  -> popularity-aware negative sampling
  -> global + personal popularity counterfactual debias head
  -> KC need constrained debiased inference
  -> 可选 CompGCN 主干升级
```

如果要在论文中突出“技术更换”，建议主方法命名为：

> **知识感知个体流行度反事实去偏推荐模型**

它比当前全局曝光正则更贴合后续方向，因为它同时满足：

1. 能直接解释和诊断 `p_base -> p_debias`。
2. 不强行追求全局均匀曝光。
3. 保留学生个性化流行度偏好。
4. 通过 KC need 保证教育相关性。
5. 与现有 Pre/In/Post 框架兼容，方便做消融。
6. 代码改动风险低于直接替换整套主干。
