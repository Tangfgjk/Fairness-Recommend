# CompGCN 原论文核对与官方源码适配说明

日期：2026-10-15；分支：`V5-20261016`。

## 核对结论

上一提交的 `semantic_compgcn.py` 只是 CompGCN 风格的原型，不能作为论文算法的忠实实现：它虽然按关系组合消息，但用了统一目标度均值聚合、额外残差与 LayerNorm；自环没有关系组合；传播后的关系表示没有进入 ConvE 解码器。此前的单批次检查只说明代码可运行，不说明算法正确或推荐有效。

本次依据用户提供的 **Vashishth et al., Composition-based Multi-Relational Graph Convolutional Networks, ICLR 2020**（本地 `参考论文/1911.03082v2.pdf`）第 4 节、式 (2)–(4) 和实验部分，以及作者的官方代码核对并修改：

- 官方仓库：<https://github.com/malllabiisc/CompGCN>（Apache-2.0）
- 官方传播层：<https://github.com/malllabiisc/CompGCN/blob/master/model/compgcn_conv.py>
- 官方模型与 ConvE 解码器：<https://github.com/malllabiisc/CompGCN/blob/master/model/models.py>

官方实现基于旧版 PyTorch / PyG 接口。本项目以当前 PyTorch 原生张量重新实现其核心计算，没有整文件复制旧依赖代码；保留同样的三种组合算子 `corr/sub/mult`、正向/逆向/自环三个权重、可学习自环关系、关系线性更新、三路均分、dropout、BatchNorm 和 tanh。默认 `corr` 与官方 ConvE 最佳示例一致，但在本项目上尚未证明是最佳设置。

## 面向教育推荐的必要适配

1. **消息图**：使用 `educational_kg_v2.npz` 的训练学生掌握、非零遗忘、习题覆盖知识点及逆边；推荐标签 `rec` 不进邻接，防止监督标签直接泄漏。
2. **连续边强度**：原论文只有离散关系。本项目用一个共享的小型投影，将掌握度或遗忘值的连续强度加入对应关系向量后再组合。这是扩展项，需要消融检验。
3. **方向归一化**：官方源码对每个方向使用同一节点度向量。教育图每个方向可为单向二部图（例如学生→知识点）；若逐字使用这一实现，只有入边的节点度为零，该方向消息可能全部被抹去。本项目分别使用源端和目标端的度，边权为 ‎1/√(源出度×目标入度)。这是针对图结构的有意调整。
4. **查询关系**：`rec` 虽不传消息，仍是可学习的查询关系并经各层关系变换。原 203 个监督关系的语义嵌入也保留，在 ConvE 解码时叠加对应的新图关系类型嵌入，因此旧特征和 KPPD 接口可沿用。这与官方直接用传播后关系作为解码输入不同，应作为本项目适配表述。
5. **检查点隔离**：训练配置写入 `compgcn_impl_version=2`、算子、dropout、层数与图 SHA-256。上一版原型的检查点不应作为新版恢复训练或推理的来源，需使用新 run 目录。

## 当前验证范围

- 新增测试检查组合算子、自环关系梯度、`rec` 查询关系梯度，以及消息图不含测试学生或推荐边。
- Algebra2005 正式图完成一次 CPU 单批次反向传播、检查点保存，以及一名测试学生的 KPPD 去偏推理。该检查仅证明实现接口连通。
- **尚未完成**：官方实现对等数值测试、三数据集完整训练、吞吐/显存测量、多种子指标、对照和消融。当前不能宣称 CompGCN 优于 ConvE，也不能把冒烟结果写成论文实验结论。

## 训练入口

`run_semantic_conve.py --backbone compgcn --compgcn-layers 1 --compgcn-op corr --compgcn-dropout 0.1`。推理入口从检查点自动读取这些设置。完整训练必须指定新的独立结果目录。
