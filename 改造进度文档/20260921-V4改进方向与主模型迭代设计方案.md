# V4 改进方向与主模型迭代设计方案

日期：2026-09-21

## 1. 当前结论

本方案基于当前最新 V3 分支：

```text
v3-debias-bias-chain-real-popularity
HEAD: 5d5ef60
```

当前代码已经不再是旧版 ConvE baseline，而是已经完成了 KPPD、BPR、tail bias 控制、raw/debiased 双推理、E0 偏差链诊断和一键主实验 runner 的 V3 强基线。

因此 V4 的方向需要重新定位：

```text
短期：把 KPPD-2CKG4ER / ConvE 做成可信、稳定、可复现的最终强基线。
中期：先升级 Educational KG schema，再用 Semantic CompGCN + KPPD 做受控的关系消息传播升级。
长期：不要停在 CompGCN，更适合作为最终主模型的是 Semantic NBFNet-style conditional KG reasoning + KPPD。
```

最重要的判断是：

```text
ConvE 不是现在最大的瓶颈。
当前 KG 是为 triple scoring 构造的，而不是为 graph reasoning 构造的。
```

因此，V4 不应直接在当前 203-relation 稠密图上硬套 CompGCN。换主干之前，应先设计一版更适合教育图推理的 **Educational KG Schema v2**。

## 2. KGE/KGR 技术演进视角

如果把技术路线简单理解为：

```text
TransE -> ConvE -> CompGCN
```

已经不够准确。

更合适的演进线是：

```text
Embedding / Scoring
-> Geometric KGE
-> Relational GNN
-> Path Reasoning
-> Inductive KGR
-> KG Foundation Model
```

### 2.1 Triple Scoring 阶段

这一阶段核心是设计三元组打分函数：

```text
f(h, r, t)
```

代表模型包括：

| 模型 | 核心思想 |
|---|---|
| TransE | h + r ≈ t，关系是向量平移。 |
| DistMult | 双线性打分，简单高效，但非对称关系表达弱。 |
| ComplEx | 复数空间双线性打分，可表达对称和反对称关系。 |
| RotatE | 复数空间旋转，强调 relation pattern。 |

这些模型共同点是：

```text
(h, r, t) -> score
```

也就是局部三元组匹配。

### 2.2 ConvE 的位置

ConvE 属于更强的 neural scorer：

```text
h, r
-> reshape
-> Conv2D
-> FC
-> score with t
```

它通过卷积增强 entity-relation feature interaction，但本质仍是：

```text
强三元组 scorer
```

而不是 multi-hop graph reasoner。

所以继续从：

```text
ConvE -> InteractE
```

对本项目意义有限。它增强的仍主要是局部 entity-relation interaction，而不是教育路径推理。

### 2.3 Relational GNN 阶段

R-GCN / CompGCN 开始真正利用整个多关系图。

CompGCN 的关键变化是：

```text
entity 和 relation 一起参与 message passing
```

也就是说，relation 不只在最后 scoring 时出现，而是在图传播中更新和组合。

这对应范式变化：

```text
Triple Scoring -> Relational Message Passing
```

因此 CompGCN 适合作为 V4 的“受控升级模型”：它能回答一个干净问题：

```text
显式 multi-relational message passing 是否比纯 triple-level interaction 更适合教育 KG？
```

### 2.4 Path Reasoning / Inductive KGR 阶段

NBFNet 之后的路线更值得关注。

NBFNet-style 方法不再只问：

```text
h, r, t 三个 embedding 是否匹配
```

而是围绕 query：

```text
(h, r, ?)
```

沿图中的路径进行条件化推理。

这与习题推荐更匹配。因为我们的推荐问题本质是：

```text
给定 learner u 和 rec query，哪些 exercise 能通过 learner 的认知状态和知识结构被解释为合适推荐？
```

典型教育路径是：

```text
u -> weak mastery KC -> exercise
u -> high forgetting KC -> exercise
```

所以从建模假设匹配度看：

```text
NBFNet-style conditional reasoning > CompGCN > ConvE
```

这不是说 benchmark 分数必然如此，而是说它更符合本项目的任务结构。

### 2.5 KG Foundation Model 暂不作为当前目标

ULTRA / TRIX / Flock / KRLM 等 KG foundation model 更关注：

```text
不同 KG
不同 entity vocabulary
不同 relation vocabulary
zero-shot transfer
```

当前项目主要目标仍是：

```text
教育 KG 内的 learner-exercise recommendation
```

因此不建议为了追求“最新”直接上 KGFM。

如果后续研究跨数据集迁移：

```text
Eedi + Algebra + XES -> zero-shot Assist2009
```

再考虑 Cross-Dataset Educational KG Foundation Model 会更合理。

## 3. 当前 V3 代码资产

当前 V3 最大资产是 KPPD 已经基本模块化。

当前正式 2CKG4ER 已经不是原始 ConvE，而是：

```text
learner: MIRT learner feature -> e_u
exercise: text + MIRT difficulty/discrimination -> e_ex
relation: relation text + continuous strength -> e_r
ConvE scorer -> z_core
KPPD head -> raw/debiased score
```

KPPD 已经拆出：

```text
z_core
z_global_pop
z_personal_pop
z_need
```

并定义：

```text
z_raw = z_core + beta_g*z_g + beta_p*z_p + beta_n*z_n
z_deb = z_raw - lambda_g*beta_g*z_g - lambda_p*beta_p*z_p
```

当前已经落地的关键代码能力：

| 能力 | 状态 |
|---|---|
| BCEWithLogits | 已实现 |
| BPR | 已实现 |
| RecPairDataset | 已实现 |
| tail bias `legacy / none / pop_branch` | 已实现 |
| raw/debiased 同 checkpoint 输出 | 已实现 |
| KPPD global/personal/need 分支 | 已实现 |
| V3 三数据集 runner | 已实现 |
| comparison models 统一公平性评价 | 已实现 |

因此未来换 backbone 时不应重写 KPPD，而是让新 backbone 输出：

```text
z_core(u, rec, exercise)
```

然后继续接：

```text
KPPDHead(z_core)
```

这使 KPPD 成为可迁移的去偏层。

## 4. 当前最大问题：KG Schema 不适合图推理

当前 ER graph 的核心问题不是 ConvE 老，而是图结构更适合 triple scoring，不适合 graph reasoning。

当前 graph 大致有：

```text
101 个 mlkc 离散关系
101 个 exfr 离散关系
1 个 rec 关系
```

而且当前构图逻辑接近：

```text
for each learner u:
  for each KC c:
    write kc --mlkc(s)--> u

for each learner u:
  for each exercise i:
    write ex_i --exfr(s)--> u
```

这会形成非常稠密的 user-exercise cognitive-state graph。

更关键的是，Q 矩阵没有真正成为 KG 边。

当前 Q matrix 被用于：

1. 计算 exercise forgetting。
2. 计算 recommendation distance。
3. 评价 KC coverage。
4. 计算 pedagogical relevance。

但正式 graph builder 中没有真正写入：

```text
exercise -> covers -> KC
```

这意味着真正有教育意义的 multi-hop path 缺失：

```text
student -> KC <- exercise
```

或者：

```text
u --low mastery--> KC_7 <--covers-- ex_25
```

如果没有 `exercise-KC` 结构，CompGCN/NBFNet 很难学到真正的教育路径。

## 5. Educational KG Schema v2

V4 换主干之前，必须先设计 Educational KG Schema v2。

推荐结构：

```text
UID -> KC        mastery(s)
UID -> KC        forgetting(s)
Exercise -> KC   covers
UID -> Exercise  rec
```

并自动加入 inverse relations：

```text
KC -> UID        inv_mastery(s)
KC -> UID        inv_forgetting(s)
KC -> Exercise   covered_by
Exercise -> UID  inv_rec
```

核心推荐路径变成：

```text
u -> KC -> exercise
```

这样图规模从当前接近：

```text
O(|U| * |E|)
```

的大量 `exfr` 边，转向：

```text
O(|U| * |KC|) + O(|Q|)
```

既减少无意义稠密边，也让图结构更符合教育解释。

### 5.1 Relation 表示方式

V4 不应继续把连续认知状态物理展开成 101 个 relation type：

```text
mlkc0.42
mlkc0.43
...
```

而应表示为：

```text
relation type + continuous edge strength
```

例如：

```text
type = mastery
strength = 0.42
```

关系 embedding 由：

```text
r_e = e_type + f_theta(strength)
```

或：

```text
r_e = MLP([type_embedding, strength_embedding])
```

生成。

逻辑 relation type 只需要：

```text
mastery
forgetting
covers
rec
```

以及它们的 inverse。

### 5.2 Schema v2 的意义

Educational KG Schema v2 是后续 CompGCN/NBFNet 的前置条件。

如果直接在旧 203-relation dense graph 上套 CompGCN，风险是：

1. 大量 user-exercise dense edges 导致 message passing 平均化。
2. 关系类型过多但语义相邻性弱。
3. `exercise-KC` 教育结构缺失。
4. 计算更重但不一定学到教育路径。
5. 可能出现 oversmoothing。

所以 V4 的第一步不是换模型，而是：

```text
KG schema upgrade
```

## 6. V4 近期必须修的代码问题

在换主干之前，当前 V3/KPPD 代码还有几个需要修正或整理的问题。

### 6.1 Popular negative 可能没有使用真实 popularity

当前逻辑中，`RecPairDataset` 的 item popularity 来自：

```text
kppd_context.item_popularity if kppd_context is not None else [1.0] * exercise_count
```

但某些消融设置中：

```text
popularity_debias = none
negative_sampling = mixed / popular
```

此时 `kppd_context = None`，popular negative 会退化成全 1 popularity，相当于没有真正使用热门负采样。

V4-A 应将：

```text
PopularityContext
```

与：

```text
KPPDHead
```

解耦。

只要：

```text
negative_sampling_mode in {popular, mixed}
```

就应加载真实 train popularity。

### 6.2 need auxiliary loss 当前没有学习意义

当前逻辑接近：

```text
need_target = components["need"].detach()
need_loss = MSE(components["need"], need_target)
```

这等于让 need 和自身拟合，loss 恒为 0 或没有训练意义。

V4-A 应重新定义 need 辅助目标：

1. 如果保留 fixed pedagogical guardrail，则不需要 need aux loss。
2. 如果需要学习 need，则 target 应来自独立教育信号，如 distance / mastery gap / forgetting。
3. 在 NBFNet 版本中，应弱化外部 need score，让 need 从 KG reasoning 中自然产生。

### 6.3 Test learner 的 personal profile 应有 neutral profile

当前 user popularity profile 可能由最大 train UID 决定。若 test learner 的 UID 超过 train 最大 UID，会映射成 invalid，personal effect 可能直接为 0。

更合理的是：

```text
unknown/test learner -> neutral personal profile
```

而不是 invalid zero effect。

### 6.4 E2 消融需要拆开 BPR 和 mixed negative

当前消融可能是：

```text
B0 = BCE + legacy tail bias
B1 = BCE + no tail bias
N1 = BCE+BPR + mixed negative
D1/D2/D3 = KPPD variants
```

这样无法区分收益来自：

```text
BPR
```

还是来自：

```text
mixed / popular negative sampling
```

建议改为：

| 方法 | 唯一变化 |
|---|---|
| B0 | legacy ConvE |
| B1 | B0 去掉 item tail bias |
| B2 | B1 + BPR + random negative |
| N1 | B2 + mixed/popular/near-boundary negative |
| D1 | N1 + global pop |
| D2 | D1 + personal pop |
| D3 | D2 + pedagogical guardrail |

这样每一步只有一个关键变量变化，论文消融更清楚。

### 6.5 Runner 与失败恢复

V3 已经出现实际中断场景。V4-A 应完善：

1. failed stage resume 时自动重跑失败 stage。
2. 允许部分模型失败但继续后续数据集。
3. 自动记录失败日志摘要。
4. 输出 `progress.csv` 和 `failed_stages.csv`。
5. 聚合脚本支持部分结果。

## 7. CompGCN 的定位：桥接模型

CompGCN 仍然推荐做，但定位应是：

```text
bridge model
```

而不是最终停留的主模型。

第一版 Semantic CompGCN 应尽量控制变量：

```text
H0 = SemanticEntityEncoder(X)
H^L = CompGCN(G_v2, H0, R)
z_core = Decoder(h_u, r_rec, h_ex)
z_raw / z_deb = KPPDHead(z_core)
```

也就是保留：

1. V3 的语义实体编码。
2. V3 的连续关系强度编码。
3. V3 的 KPPDHead。
4. 尽量相近的 decoder。

唯一主要变化是：

```text
No Graph Propagation -> Relational Graph Propagation
```

这样能回答：

```text
显式多关系消息传播是否优于 ConvE triple interaction？
```

### 7.1 CompGCN 实验组

至少需要：

| 方法 | 目的 |
|---|---|
| ConvE baseline | V3 原始主干 |
| KPPD-ConvE | V3 强基线 |
| CompGCN baseline | 只换主干，不加 KPPD |
| KPPD-CompGCN | 主干 + 去偏 |

如果没有 `CompGCN baseline`，就无法判断 KPPD 和 graph propagation 各自贡献。

## 8. 长期主模型：Semantic NBFNet + KPPD

本项目最终更适合 NBFNet-style conditional reasoning。

原因是推荐任务天然是 query-conditioned：

```text
(u, rec, ?)
```

给定 learner query，需要沿教育 KG 路径寻找合适 exercise。

当前 test learner 设置也支持这个方向：

```text
train learner: 有 rec supervision
test learner: 只有 cognitive edges，没有 rec supervision
```

标准 KGE 的 ID embedding 对 test learner 不理想，而 NBFNet / inductive message passing 更符合：

```text
新 learner 只根据 cognitive edges 做推荐
```

### 8.1 NBFNet 中 need 的变化

到了 NBFNet，不建议继续直接喂：

```text
stu2ex_recommend_full_precision.json
```

因为它本身接近生成 `rec` 标签的 teacher heuristic。若新 backbone 还直接使用这个矩阵，就会削弱“通过 KG reasoning 学习 educational need”的意义。

NBFNet 版应让 need 从图中推理出来：

```text
u --mastery/forgetting--> KC --covers--> exercise
```

模型自己学习：

```text
u -> KC message
KC -> exercise message
```

如何组合成：

```text
z_core(u, rec, exercise)
```

此时：

```text
NBFNet solves: student really needs what?
KPPD solves: model score is biased toward popular resources or not?
```

两者分工清楚。

### 8.2 NBFNet + KPPD 结构

建议结构：

```text
Learner features
Mastery / Forgetting
Exercise text / IRT
Q matrix
       |
       v
Educational KG Schema v2
       |
       v
Semantic relation encoder
type + continuous strength
       |
       v
Conditional KG reasoner
NBFNet-style
       |
       v
z_core(u, rec, exercise)
       |
       +----------------+
       |                |
       v                v
Global Pop        Personal Pop
       |                |
       +--------+-------+
                v
              KPPD
                |
          raw / debiased
```

这条路线的论文故事更完整：

```text
Pedagogical State Modeling
-> Educational KG Reasoning
-> Popularity Debiasing
```

## 9. 后续技术路线分阶段

建议路线：

| 阶段 | 模型 / 任务 | 目的 | 判断 |
|---|---|---|---|
| S0 | 当前 KPPD-2CKG4ER | 完成强 ConvE baseline | 当前先做完 |
| S1 | Educational KG Schema v2 | Q 边 + mastery/forgetting KC edge + continuous strength | 换主干前必须做 |
| S2 | Semantic CompGCN + KPPD | 验证 relational propagation | 下一个模型 |
| S3 | Semantic NBFNet + KPPD | query-conditioned multi-hop educational reasoning | 最值得作为最终主方法 |
| S4 | A*Net-style + KPPD | 大图路径推理加速 | 有性能瓶颈再做 |
| S5 | ULTRA/Flock-style | 跨教育 KG zero-shot | 后续研究 |
| S6 | LLM + KG reasoning | 文本开放域推理 | 当前不建议 |

## 10. V4 实验设计

### 10.1 V4-A：修复与复现实验

目标：先把 V3 跑稳。

内容：

1. 修复 KPPD/BPR/popular negative/need/profile 等问题。
2. 完成 V3 三数据集主实验。
3. 输出稳定结果表。

方法：

```text
baseline
in_kppd
pre_in_kppd_post
```

### 10.2 V4-B：Schema v2 验证实验

目标：验证 Educational KG Schema v2 是否比旧 graph 更适合教育推荐。

对比：

```text
ConvE on old schema
ConvE on schema v2
CompGCN on schema v2
```

重点不是马上追求最高分，而是确认：

1. Q edges 进入图后是否提高教育相关指标。
2. 稀疏 KC-centric graph 是否降低计算成本。
3. E0 偏差链是否更可解释。

### 10.3 V4-C：Semantic CompGCN + KPPD

目标：验证关系消息传播。

方法：

```text
ConvE baseline
KPPD-ConvE
Semantic CompGCN
Semantic CompGCN + KPPD
```

### 10.4 V4-D：Semantic NBFNet + KPPD

目标：验证 conditional educational KG reasoning。

方法：

```text
KPPD-ConvE
KPPD-CompGCN
Semantic NBFNet
Semantic NBFNet + KPPD
```

如果 NBFNet 太慢，再考虑 A*Net-style 加速。

## 11. 指标体系

V4 继续沿用 V3 指标，避免评价口径漂移。

推荐质量：

```text
Ada@10,20,50,100
NOV@10,20,50,100
Ep_sim@10
```

资源去偏：

```text
ItemExposureGini
KCExposureGini
ItemCoverage
KCCoverage
HeadItemExposureShare
HeadKCExposureShare
LongTailItemExposureShare
LongTailKCExposureShare
```

偏差链：

```text
p_data -> p_label -> p_raw -> p_debiased
```

Schema v2 后应额外关注：

```text
路径解释质量
KC path coverage
u -> KC -> exercise path evidence
```

但这些解释指标应作为补充，不替代主指标。

建议不要直接叫：

```text

```

因为 V4 的第一步其实是 schema upgrade。

建议分支：

```text
v4-educational-kg-schema
```

或分阶段：

```text
v4-schema-v2
v4-compgcn-kppd
v4-nbfnet-kppd
```

## 13. 最终建议

当前不要急着实现 V4。

下一步顺序应为：

1. 修复并续跑当前 V3 实验。
2. 分析 V3 三数据集结果。
3. 固化 KPPD-2CKG4ER 作为 ConvE 强基线。
4. 修复 popular negative、need aux、neutral profile、E2 消融拆分等问题。
5. 设计并实现 Educational KG Schema v2。
6. 在 Schema v2 上做 Semantic CompGCN + KPPD。
7. 如果 CompGCN 证明 graph propagation 有效，再推进 Semantic NBFNet + KPPD。

一句话总结：

```text
V3 的核心是把 ConvE-Debias 做稳；
V4 的核心不是直接换 CompGCN，而是先把 KG 从 triple-scoring schema 升级成 educational reasoning schema；
最终主模型方向应是 Semantic NBFNet-style conditional reasoning + KPPD。
```
