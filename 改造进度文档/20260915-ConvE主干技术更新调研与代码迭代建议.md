# ConvE 主干技术更新调研与代码迭代建议

日期：2026-09-15

## 1. 结论先行

当前 2CKG4ER 的主模型仍以 ConvE 风格的知识图谱三元组打分为核心。ConvE 本身已经偏旧，它适合作为稳定 baseline，但不适合作为后续论文的唯一技术主干。

不过，不建议在当前 E0/E1 去偏实验尚未完全跑完时直接替换 ConvE。更合理的顺序是：

1. 先保留 ConvE，完成多数据集偏差链诊断和 Pre/In/Post 消融，固化“是否存在偏差放大、当前去偏是否有效”的证据。
2. 再做低风险训练侧升级：加入 BPR/pairwise ranking loss、popular/hard negative sampling，让训练目标更接近 Top-K 推荐。
3. 然后做主干升级：在保留现有输入输出接口的前提下，引入 CompGCN 或轻量关系感知 GNN encoder，让模型从“局部三元组打分”升级到“多关系教育 KG 传播”。
4. 最后再叠加与当前方向最一致的去偏模块：全局流行度分支、个人流行度分支、知识需求约束、反事实分数校正、流行度衰减图对比学习。

换句话说，下一阶段的技术更新不应该简单表述为“把 ConvE 换掉”，而应该表述为：

> 在统一真实训练交互口径和偏差链诊断的基础上，将旧式 KGE 推荐模型逐步升级为面向 Top-K 推荐、教育知识图谱传播和资源流行度去偏的模块化框架。

## 2. 已有项目文档中的判断

项目里已经有一份主模型更新调研：

- `引用依据论文/20260902-173401-主模型训练测试技术更新论文调研与改造建议.md`

该文档已经明确指出：

- 当前 `semantic_conve_model.py` 主体是 ConvE 风格三元组打分。
- 当前训练目标以 pointwise BCE 为主。
- 当前负采样是随机负采样，和推荐排序目标存在距离。
- 推荐第一优先升级为 CompGCN。
- 推荐加入 BPR/pairwise ranking loss。
- 推荐后续加入 KGCL/KGTN 类对比学习与去噪。
- KT/LLM 更适合作为后续增强，而不是第一步直接替换主模型。

本次补充调研后的判断与该文档一致，但结合 2025-2026 的新论文和当前去偏方向，需要把升级路线重新排序：先做推荐目标和采样升级，再做 KG 主干升级，再做反事实/对比去偏增强。

## 3. 技术演变脉络

### 3.1 ConvE/KGE 阶段

ConvE 将 KG 链接预测建模为 `(head, relation, tail)` 的打分问题，适合对 `student - rec - exercise` 这类边进行预测。当前代码正是沿用这一范式。

优点：

- 实现简单，训练稳定。
- 与当前 `entities.dict / relations.dict / triples.txt` 格式兼容。
- 方便作为所有新方法的固定 baseline。

问题：

- 主要是局部三元组打分，没有显式多跳图传播。
- pointwise BCE 把推荐训练成二分类问题，和 Top-K 排序目标不完全一致。
- 对热门习题/热门知识点的频繁训练更新可能放大训练数据偏差。

### 3.2 KG-GNN 推荐阶段

KGAT、CompGCN、KGIN、KGTN 等方法把知识图谱从“被打分的三元组集合”升级为“可以传播和聚合的多关系图”。其中 CompGCN 与当前项目最兼容，因为它直接面向多关系图，同时更新实体和关系表示。

对本项目的意义：

- 可以复用现有教育 KG。
- 可以把学生、习题、知识点、文本语义、MIRT 特征统一到图传播后的表示中。
- 可以保留 `score_tails_logits` 一类接口，从而减少对评估、rerank、公平性指标脚本的破坏。

优先级判断：

- CompGCN：第一优先主干升级。
- KGAT/KGIN：可作为对比或参考，不一定优先实现。
- KGTN/Graph Transformer：中期方向，依赖和实现成本较高。

### 3.3 推荐目标升级阶段

教育推荐最终关心的是每个学生的 Top-K 推荐结果，不是单个三元组是否为真。因此，BPR、pairwise ranking、listwise/top-K-aware loss 比单纯 BCE 更贴近任务。

对当前代码的直接落点：

- 在 `training_objectives.py` 中新增 `bpr_loss` 或 `bce_bpr_loss`。
- 在 `run_semantic_conve.py` 中新增 `--training-objective bce|bpr|bce_bpr`。
- 训练 batch 中同时采样正习题和负习题，优化 `score(u, pos) > score(u, neg)`。
- 仍保留 BCE，方便消融：`ConvE+BCE` vs `ConvE+BPR` vs `ConvE+BCE+BPR`。

这一步比立刻实现 CompGCN 更低风险，而且可以直接提升推荐训练目标与 Ada/NOV/Fairness 评价之间的一致性。

### 3.4 去偏推荐阶段

当前项目已经从“习题/知识点公平性”调整为“面向学生学习机会的资源流行度去偏”。因此，后续模型内技术更新应优先围绕流行度偏差，而不是单纯追求习题平均曝光。

最匹配的近期方向是：

- 全局流行度分支：学习 item 的整体 popularity effect。
- 个人流行度分支：学习学生对热门/长尾资源的个性化偏好。
- 知识需求约束：避免为了去热门而推荐教育上不相关的习题。
- 反事实分数校正：推理时从主分数中扣除或调节 popularity 分数。
- 流行度衰减图/反事实图：降低热门交互边权重，构造 original graph 与 counterfactual graph 双视图。
- 对比学习一致性：要求去流行度视图下仍保留教育相关表示。

这一路线比“全局均匀曝光正则”更适合作为论文主方法，因为它能解释为：在教育相关性约束下减少模型对热门资源的偏差放大。

### 3.5 知识追踪与学生状态阶段

simpleKT、AKT、DTransformer、UKT、LLM-KT 等工作说明，最新教育推荐/知识追踪越来越强调动态学生状态。当前代码虽然使用了 MIRT、MLKC、forgetting 等特征，但主模型里没有端到端地建模学生历史答题序列。

不过，学生侧学习机会公平诊断是最后阶段要做的事情，所以 KT 升级暂时不应抢在资源去偏主线前面。

建议顺序：

1. 先把 KT 模型作为外部 student state encoder，输出学生状态向量。
2. 再把该向量接入现有 `student_features` 或模型 fusion 层。
3. 最后再做学生侧分组公平评价。

这样可以避免过早改变问题定义。

### 3.6 LLM 增强阶段

2025-2026 的教育推荐论文开始使用 LLM 增强资源语义、知识点解释和学习路径理解。但已有证据也提醒：直接用通用 LLM 替代专门 KT 模型并不稳妥。

因此本项目不建议把主模型直接换成 LLM。更合适的是：

- 用 LLM 或预训练语言模型生成习题语义 embedding。
- 用 LLM 生成知识点解释、难度理由、先修关系描述。
- 把这些作为冻结特征输入 KG/GNN/KT 模型。

LLM 在本项目中的定位应是 semantic enhancer，而不是 recommender backbone。

## 4. 当前代码检查结论

本次检查的核心代码包括：

- `Code/codes-New-ConvE/semantic_conve_model.py`
- `Code/codes-New-ConvE/run_semantic_conve.py`
- `Code/codes-New-ConvE/training_objectives.py`
- `Code/codes-New-ConvE/fairness_regularizer.py`
- `Code/codes-New-ConvE/feature_loader.py`

### 4.1 主模型仍是 ConvE 局部打分

`semantic_conve_model.py` 中的 `TwoCKG4ER` 负责实体/关系 embedding、语义特征融合和 ConvE 打分。核心仍是 `conve_transform`、`score_triples_logits`、`score_tails_logits`。

这说明当前模型虽然融合了教育语义特征，但图结构使用方式仍偏旧：它没有先通过多关系 GNN 对学生、习题、知识点进行消息传播，再做推荐打分。

### 4.2 训练目标仍是 weighted BCE

`training_objectives.py` 目前主要提供 `weighted_bce_loss`。`run_semantic_conve.py` 训练循环中使用该 loss 训练正负三元组。

这适合链接预测，但不完全适合推荐排序。后续应加入 BPR/pairwise ranking loss，并把它作为第一轮技术更新实验。

### 4.3 负采样策略仍比较简单

`run_semantic_conve.py` 的 `TripleDataset` 只对 `rec` relation 做 type-constrained filtered tail replacement。负样本主要是随机习题。

后续可以新增：

- `random`：保留当前逻辑。
- `popular`：从热门习题中采负样本，测试模型是否能区分“热门但不适合”。
- `hard`：从当前模型高分但未交互习题中采负样本。
- `mixed`：random + popular + hard。

这一步与 popularity debias 主线高度相关。

### 4.4 公平正则已有基础，但需要从均匀曝光转向因果/偏好分解

`fairness_regularizer.py` 已有 expected exposure regularizer，并支持 `random/popular/top_score/mixed/mixed_user` 候选模式。

它适合当前 E1 的 in-processing 消融，但论文主方法不应只停留在“把曝光拉均匀”。后续更强的模型内方法应拆解为：

- 主推荐分数 `s_main(u, i)`。
- 全局流行度分数 `s_global_pop(i)`。
- 个人流行度偏好分数 `s_personal_pop(u, i)`。
- 知识需求约束分数 `s_need(u, kc(i))`。
- 推理分数校正：`s_final = s_main - lambda_g * s_global_pop - lambda_p * s_personal_pop + lambda_k * s_need`。

其中 `lambda` 可以通过验证集调参，并用 E0 偏差链观察校正前后是否减少 `p_base -> p_debias` 的偏差放大。

### 4.5 当前评估链路已经适合支撑技术更新

近期新增的真实训练交互口径、E0 偏差链诊断、E1 消融实验，是后续主模型更新的必要前置条件。

因此，接下来不应另起一套评价，而应继续沿用：

- Ada/NOV/Fairness。
- `p_data / p_label / p_base / p_debias`。
- Gini、JS、ARP、Head/Mid/Tail exposure。
- Pre/In/Post 单模块和组合消融。

这能保证技术更新不是只看推荐准确率，而是同时观察偏差放大和去偏效果。

## 5. 建议的技术迭代路线

### P0：完成当前多数据集 E0/E1

目标：证明问题存在、证明当前 Pre/In/Post 是否有效。

不改主模型，只跑完：

- E0 bias-chain。
- E1 baseline/pre/in/post 消融。
- 四个剩余数据集。

产出：

- 每个数据集的偏差链表。
- 每个数据集的消融表。
- 是否存在跨数据集一致现象。

### P1：BPR 与负采样升级

目标：让训练目标从三元组二分类更接近 Top-K 推荐。

建议实现：

- 新增 `--training-objective bce|bpr|bce_bpr`。
- 新增 `--negative-sampling-mode random|popular|mixed`，hard negative 可放第二步。
- 在 `training_config.json` 中记录 objective 和 sampler。
- 实验先只在 Eedi + algebra2005 跑小规模验证。

消融：

| 编号 | 方法 | 目的 |
|---|---|---|
| T0 | ConvE + BCE + random negative | 当前 baseline |
| T1 | ConvE + BPR + random negative | 验证排序损失 |
| T2 | ConvE + BCE+BPR + random negative | 验证混合目标 |
| T3 | ConvE + BPR + popular negative | 验证热门负样本约束 |
| T4 | ConvE + BPR + mixed negative | 验证采样组合 |

### P2：CompGCN 主干升级

目标：把局部三元组打分升级为多关系教育 KG 表示学习。

建议实现：

- 保留 `TwoCKG4ER` 作为 `backbone=conve`。
- 新增 `backbone=compgcn`。
- 先实现轻量 `CompGCNEncoder`，输入全部训练 triples 的 edge index 和 relation id。
- 编码后仍复用现有 tail scoring 接口，减少评估脚本改动。
- 第一版不引入复杂 dependency，优先 PyTorch 原生实现。

消融：

| 编号 | 方法 | 目的 |
|---|---|---|
| G0 | ConvE + BCE | 旧主干 |
| G1 | CompGCN + BCE | 单看图传播是否有效 |
| G2 | CompGCN + BPR | 图传播 + 排序目标 |
| G3 | CompGCN + BPR + current in-regularizer | 与当前模型内去偏衔接 |

### P3：资源流行度反事实分支

目标：形成与论文主线最贴合的模型内去偏方法。

建议实现：

- `PopularityDebiasHead`：
  - 全局 item popularity embedding/MLP。
  - 学生个人流行度偏好 embedding/MLP。
  - KC need gate。
- 训练时同时优化推荐目标和 popularity prediction/control objective。
- 推理时输出 raw score、popularity score、debiased score。
- E0 诊断中新增 `p_raw_model` 与 `p_corrected_model` 对照。

核心证明：

- 原模型是否从 `p_data` 放大到 `p_base`。
- 加入分支后是否从 `p_base` 缓解到 `p_debias`。
- Ada/NOV 是否没有明显崩坏。

### P4：流行度衰减图与对比学习

目标：引入 CORE/KGCL/CounterCLR 思路，使模型不仅在分数层扣 popularity，还在表示学习阶段降低热门边主导。

建议实现：

- 原图 `G`。
- 反事实图 `G_cf`：按 item popularity 对 `rec` 边降权或采样丢弃。
- 双视图编码：`z = encoder(G)`，`z_cf = encoder(G_cf)`。
- 对比约束：保持同一学生/习题在两视图下的教育语义一致，同时降低热门边带来的表示支配。

这一步适合在 CompGCN 主干稳定后做，不适合抢在 P1/P2 前面。

### P5：学生状态编码器

目标：为最终学生侧学习机会公平诊断做准备。

建议实现：

- 第一版使用外部 KT 模型产生静态/时间切片学生状态向量。
- 接入现有 `student_features`。
- 后续再考虑 simpleKT/UKT 端到端联合训练。

注意：这一步暂时不是当前最优先任务，因为用户已经明确学生侧公平诊断最后做。

### P6：LLM 语义增强

目标：提升习题和知识点文本语义，不改变推荐主问题。

建议实现：

- 为习题文本、知识点说明生成 frozen semantic embedding。
- 替换或补充当前 BiGRU 文本特征。
- 只作为特征增强，不作为主推荐模型。

## 6. 不建议现在做的方向

1. 不建议直接把 ConvE 替换为复杂 Transformer/KGTN。
   当前实验主线是去偏，过早换复杂主干会让偏差链证据和模型能力变化混在一起。

2. 不建议第一步做强化学习习题推荐。
   ExRec 等工作很新，但会把任务从 Top-K 推荐扩展到长期学习收益优化，问题定义变化太大。

3. 不建议直接上纯 LLM 推荐。
   近期 KT 论文仍显示专门 KT 模型在学生状态预测上更稳，LLM 更适合作为语义增强器。

4. 不建议继续扩大“均匀曝光”正则作为主方法。
   它可以作为 baseline，但论文主方法应强调教育相关性约束下的 popularity debias。

## 7. 近期最应该做的代码任务

按照风险和收益排序：

1. 为 `run_semantic_conve.py` 加入训练目标开关：`bce|bpr|bce_bpr`。
2. 为 `TripleDataset` 或新 sampler 加入 `random|popular|mixed` 负采样。
3. 把 `train_interactions` popularity 继续作为 sampler、fairness、rerank、diagnostics 的默认来源。
4. 抽象模型接口：至少保证新主干都实现 `score_triples_logits` 和 `score_tails_logits`。
5. 新增 `backbone=conve|compgcn`，先做 CompGCN 最小可用版。
6. 新增 popularity debias head，并在 E0 诊断中输出 raw/corrected 两组分布。
7. 长跑实验脚本支持更强 resume/skip，避免大数据集在某一组中断后重复跑。

## 8. 推荐实验矩阵

当前 E0/E1 完成后，建议进入 E2 技术更新实验：

| 阶段 | 方法 | 主要问题 |
|---|---|---|
| E2-T0 | ConvE + BCE | 当前固定 baseline |
| E2-T1 | ConvE + BPR | 排序损失是否提升推荐质量 |
| E2-T2 | ConvE + BCE+BPR | 混合目标是否更稳 |
| E2-T3 | ConvE + BPR + popular negative | 热门负样本是否减少热门偏差 |
| E2-G1 | CompGCN + BCE | 图传播是否优于旧 ConvE |
| E2-G2 | CompGCN + BPR | 图传播与排序目标是否互补 |
| E2-D1 | ConvE/CompGCN + popularity debias head | 模型内反事实分数校正是否有效 |
| E2-D2 | D1 + post rerank | 模型内去偏与后处理是否互补 |
| E2-C1 | D1 + counterfactual graph contrastive | 表示层去偏是否进一步改善 |

先在 Eedi 与 algebra2005 做小规模验证，再扩展到剩余数据集。

## 9. 对论文叙事的影响

后续论文可以这样组织技术贡献：

1. 重新定义问题：从习题/KC 静态公平，转向面向学生学习机会的资源流行度去偏。
2. 诊断问题：提出教育推荐偏差链 `p_data -> p_label -> p_base -> p_debias`。
3. 稳定基线：保留 ConvE 作为旧 2CKG4ER baseline。
4. 训练目标升级：引入 Top-K 排序导向的 BPR 和 popularity-aware negative sampling。
5. 主干升级：从 ConvE 到多关系教育 KG GNN。
6. 去偏方法：通过全局/个人 popularity 分支和知识需求约束做反事实分数校正。
7. 扩展验证：最终回到学生侧学习机会公平，证明资源去偏是否真的让不同学生群体获得更稳定的学习机会。

这样比单纯说“我们换了一个新模型”更严谨，也更贴合目前已经完成的 E0/E1 工作。
