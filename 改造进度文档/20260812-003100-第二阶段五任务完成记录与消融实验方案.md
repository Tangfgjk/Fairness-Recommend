所有新增能力均采用默认关闭或独立输出目录：

- 一键实验流水线把每个方法放到独立目录，便于消融和对比。

## 2. 任务 1：抽取公平上下文

新增文件：

`E:\Fairness-aware\2CKG4ER\Code\codes-New-ConvE\fairness_context.py`

完成内容：

1. 读取 `Q.txt`，构造 `exercise_to_kc`。
2. 读取 `triples.txt`，统计 `item_popularity`。
3. 根据 `item_popularity + Q.txt` 推导 `kc_popularity`。
4. 生成 `item_long_tail_flag` 和 `kc_long_tail_flag`。
5. 生成 `ex_kc_matrix`，用于训练阶段将 item exposure 聚合到 KC exposure。
6. 生成 popularity-smoothed target distribution：

```text
target = normalize((popularity + epsilon) ** gamma)
```

这样做的原因是：完全均匀曝光不一定符合教育推荐场景，平滑热门度目标可以削弱热门资源优势，同时保留教育资源本身被使用频率的合理差异。

该模块提供两个核心接口：

```python
build_fairness_context(data_dir, head_ratio, long_tail_ratio, target_gamma)
context.to_tensors(device)
```

后续评估、重排、模型内公平正则都可以复用同一套公平上下文，避免重复实现。

## 4. 任务 3：加入关系 Loss 权重

新增文件：

`E:\Fairness-aware\2CKG4ER\Code\codes-New-ConvE\training_objectives.py`

修改文件：

`E:\Fairness-aware\2CKG4ER\Code\codes-New-ConvE\run_semantic_conve.py`

新增参数：

```text
--relation-loss-weights none|balanced|custom
--rec-loss-weight
--mlkc-loss-weight
--exfr-loss-weight
--exkc-loss-weight
--other-loss-weight
```

实现方式：

- `none`：所有关系权重为 1，等价于原始训练。
- `balanced`：按关系组数量做反频率加权，让 `rec` 不被大量 `exfr` 三元组淹没。
- `custom`：使用命令行传入的手动权重。

当前关系组：

| 关系组 | 包含关系 |
| --- | --- |
| `rec` | `rec` |
| `mlkc` | `mlkc0.xx` |
| `exfr` | `exfr0.xx` |
| `exkc` | `ex_has_kc`、`kc_has_ex` |
| `other` | 其他关系 |

训练中原本的：

```python
binary_cross_entropy(pred, label)
```

已经替换为：

```python
weighted_bce_loss(pred, label, r, relation_weight_tensor)
```

不加新参数时，结果与原始 BCE 等价。

## 5. 任务 4：加入模型内公平正则

新增文件：

`E:\Fairness-aware\2CKG4ER\Code\codes-New-ConvE\fairness_regularizer.py`

修改文件：

`E:\Fairness-aware\2CKG4ER\Code\codes-New-ConvE\run_semantic_conve.py`

新增参数：

```text
--fairness-loss none|expected_exposure
--fairness-alpha-item
--fairness-alpha-kc
--fairness-temperature
--fairness-candidate-size
--fairness-target-gamma
--fairness-head-ratio
--fairness-long-tail-ratio
```

实现思想：

1. 在训练 batch 中找出 `rec` 关系对应的用户。
2. 为这些用户采样一批候选习题。
3. 计算 `score(uid, rec, ex)`。
4. 用 softmax 近似推荐曝光概率：

```text
softmax(score / temperature)
```

5. 得到期望 item exposure。
6. 通过 `ex_kc_matrix` 聚合得到期望 KC exposure。
7. 分别与 item/KC 的平滑目标曝光分布做 MSE。
8. 总 loss 为：

```text
loss = weighted_bce_loss + alpha_item * item_fair_loss + alpha_kc * kc_fair_loss
```

默认：

```text
--fairness-loss none
--fairness-alpha-item 0.0
--fairness-alpha-kc 0.0
```

因此不会影响原始 baseline。

训练完成后，如果启用了公平正则，会额外写入：

```text
fairness_context.json
fairness_regularizer_config.json
```

用于记录公平上下文、候选数、目标分布、item/KC 正则权重等。

## 7. 消融/对比实验设计

第一轮仍然只建议用 Eedi seed2024，不做多 seed，不做参数敏感性。

### 7.1 主消融顺序

| 顺序 | 实验 | 主要回答的问题 |
| ---: | --- | --- |
| 1 | `baseline` | 原始模型公平性问题有多严重 |
| 2 | `fairkg_edges` | 只把 `Q.txt` 变成 KG 边是否改善 KC 公平 |
| 3 | `fairkg_weighted` | 关系数量不均衡是否影响推荐公平 |
| 4 | `fairreg_item` | item 期望曝光正则是否改善习题覆盖和长尾曝光 |
| 5 | `fairreg_kc` | KC 期望曝光正则是否改善知识点覆盖和长尾曝光 |
| 6 | `fairreg_item_kc` | item/KC 联合正则是否比单独正则更均衡 |
| 7 | `fairreg_item_kc_hybrid_rerank` | 模型内公平和后处理公平是否互补 |

### 7.2 分析指标

质量指标：

```text
Ada@K
NOV@K
```

公平性指标：

```text
ItemExposureGini@K
KCExposureGini@K
ItemCoverage@K
KCCoverage@K
LongTailItemExposureShare@K
LongTailKCExposureShare@K
```

重点看 `K=10, 20, 50, 100`，其中：

- `K=10` 更接近短推荐列表。
- `K=50` 适合观察中等长度推荐列表的公平性。
- `K=100` 适合观察整体资源覆盖。

### 7.3 预期判断标准

一个方法值得保留，需要满足：

1. Ada 不应大幅下降。
2. NOV 尽量保持或略升。
3. ItemCoverage 和 KCCoverage 至少一个明显提升。
4. ItemExposureGini 和 KCExposureGini 至少一个下降。
5. LongTailItemExposureShare 或 LongTailKCExposureShare 有提升。
6. 如果公平性提升完全来自后处理，而模型内方法无贡献，则论文主方法应重新定位。
