## 5. MCP 日志异常问题与处理结果

### 5.1 问题现象

```

日志中反复出现：

Received exception from stream: 6 validation errors for JSONRPCMessage

```

### 5.2 原因分析

该日志不是实验代码产生的，而是 Codex 的 `filesystem` MCP 服务产生的。

进程链为：

```text
codex.exe
  -> mcp-filesystem.exe --stdio
    -> python.exe
      -> D:\anaconda3\python.exe ... mcp-filesystem.exe --stdio
```

本地包中存在如下日志配置：

```python
logging.StreamHandler(sys.stdout)
logging.FileHandler('mcp_filesystem.log', encoding='utf-8')
print("启动MCP FileSystem Server，传输协议: stdio")
mcp.run(transport="stdio")
```

问题在于：`stdio` 模式下，`stdout` 应该只传输 MCP JSON-RPC 协议消息，但该服务向 `stdout` 输出普通日志和 `print` 信息，导致通信流被污染，触发重复报错并持续写入日志。

### 5.3 已处理结果

已关闭 Codex 中的 `filesystem` MCP，并手动结束残留进程：

```powershell
Stop-Process -Id 21704,22152,20912 -Force
```

已清空日志：

```powershell

```

随后连续观察 10 秒：

```text
SizeMB1: 0
SizeMB2: 0
DeltaMB: 0
```

结论：日志增长已经停止。

后续注意：

- 不建议重新打开 `filesystem` MCP。
- 如需重新打开，应先修复它的日志配置，避免再次写满 E 盘。
