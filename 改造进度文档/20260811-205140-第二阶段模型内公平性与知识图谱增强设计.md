## 1. 当前结论

当前代码已经不是完全没有知识图谱。它使用 `entities.dict`、`relations.dict`、`triples.txt` 训练三元组，并用 ConvE 风格打分函数学习 `uid / kc / ex` 三类实体以及 `rec / mlkc / exfr` 三类关系。

但当前 KG 使用方式仍然偏弱，主要问题是：

1. `Q.txt` 中的 `exercise -> knowledge concept` 映射没有作为 KG 边进入训练，只在评估和重排阶段用于计算 KC 暴露。
2. 推荐目标仍然是 `score(uid, rec, ex)`，训练 loss 只做 BCE，没有显式约束 item/KC 曝光公平。
3. 负采样只对 `rec` 关系生效，`mlkc` 和 `exfr` 只作为正样本出现，容易让训练目标被大规模认知关系三元组主导。
4. `rec` 训练边来自前置 Top-10 推荐构图，本身已经带有热门习题和热门知识点偏置，模型会继承并放大这种偏置。
5. KC 实体当前基本只保留 ID 表示，没有充分利用知识点语义、习题归属结构和公平约束。

因此，下一步不应简单“再写一个重排脚本”，而应做一个 KG-aware fairness 改造：让模型训练时看到习题和知识点结构，并在训练目标中显式控制习题与知识点曝光倾向。

## 3. 为什么要把 KG 纳入公平性改造

我们当前关注的是习题公平和知识点公平。习题公平可以直接看 `uid -> ex` 推荐曝光，但知识点公平必须依赖 `ex -> kc` 映射。现在 `Q.txt` 只在评估阶段被使用，所以模型本身并不知道某个习题覆盖哪些知识点，也不知道推荐集中在少数知识点会造成学习机会不均。

把 KG 纳入公平性改造有三个必要性：

1. **让 KC 公平从评价指标变成训练信号。**  
   如果不把 `ex -> kc` 结构交给模型，KC 公平只能在重排阶段补救，模型训练本身仍可能持续偏向热门 KC。

2. **保留并增强可解释性。**  
   原模型已有 `uid / kc / ex` 三类实体和认知关系。加入 `ex_has_kc` 后，可以形成更自然的解释路径：学生状态 -> 薄弱/遗忘知识点 -> 覆盖该知识点的习题 -> 公平性约束下的推荐。

3. **避免公平性只是列表层面的表面调整。**  
   后处理重排能改善最终 Top-K，但无法改变底层表示学习。模型内公平改造可以让长尾习题和长尾知识点获得更合理的表示与分数。

## 4. 建议的总体改造路线

第二阶段接下来建议从易到难分成四个小阶段。

### 4.1 阶段 A：KG 结构补全

目标：把 `Q.txt` 中的习题-知识点关系显式写入训练图。

新增关系建议：

| 关系名 | 三元组方向 | 含义 |
| --- | --- | --- |
| `ex_has_kc` | `ex -> kc` | 习题覆盖某个知识点 |
| `kc_has_ex` | `kc -> ex` | 反向边，便于 KG 模型学习从知识点到习题的传播 |

需要做的事情：

1. 新增图增强脚本，例如 `prepare_fair_kg_graph.py`。
2. 输入原始 `er_graph`，读取 `Q.txt`。
3. 输出新目录，例如 `Data_Fin\Eedi\fair_kg_graph`，不要覆盖原始图。
4. 在新目录中复制原有 `entities.dict`、`semantic_kg_features`、`stu2know_*` 等文件。
5. 扩展 `relations.dict`，新增 `ex_has_kc` 和 `kc_has_ex`。
6. 扩展 `triples.txt`，加入 `ex{i} ex_has_kc kc{j}` 和 `kc{j} kc_has_ex ex{i}`。
7. 写入 `fair_kg_graph_manifest.json`，记录新增边数量、Q 矩阵维度、源目录和生成参数。

为什么这样做：

- 这是最低风险的 KG 增强，不改模型结构，只改训练图。
- 可以直接和 baseline 对照：`2CKG4ER` vs `2CKG4ER + ex-kc KG edges`。
- 如果只加边就能改善 KC 覆盖，论文里可以说明知识结构显式建模对公平性有帮助。

注意：

- 这一步不是预处理“裁剪”，而是结构补全。
- 必须保留原始图目录，保证 baseline 可复现。
- 测试生成的临时数据必须放在临时目录，测试结束删除。

### 4.2 阶段 B：关系采样和 loss 权重

目标：解决 `exfr` 三元组远多于 `rec` 的训练不均衡问题。

需要新增一个训练采样/加权模块，例如：

`training_objectives.py`

核心接口建议：

```python
def relation_loss_weight(relation_name: str, config: RelationWeightConfig) -> float:
    ...
```

或：

```python
class TrainingObjective:
    def compute_loss(self, model, batch, context) -> torch.Tensor:
        ...
```

第一版可以只做关系权重：

| 关系类型 | 建议处理 |
| --- | --- |
| `rec` | 权重最高，因为最终任务是推荐 |
| `mlkc` | 中等权重，提供学生知识掌握结构 |
| `exfr` | 降权，避免数量过大淹没推荐目标 |
| `ex_has_kc / kc_has_ex` | 中等或较低权重，提供结构约束 |

为什么这样做：

- 当前训练三元组数量极不均衡，直接 BCE 会让模型偏向重构大关系。
- 公平性推荐最终看 `uid -> ex`，不能让 `rec` 训练信号被边数规模压住。
- 关系权重是模型内改造中最轻量的一步，便于做消融。

建议消融：

1. `baseline`
2. `+ ex-kc KG edges`
3. `+ relation loss weight`
4. `+ ex-kc KG edges + relation loss weight`

### 4.3 阶段 C：模型内公平性正则

目标：让公平性指标不只发生在重排，而是进入训练目标。

建议新增独立模块：

`fairness_regularizer.py`

核心接口建议：

```python
class FairnessRegularizer:
    def __call__(self, model, user_ids, candidate_exercise_ids, q_matrix) -> torch.Tensor:
        ...
```

第一版建议使用“可微的期望曝光”思想：

1. 对一个 batch 的用户采样一批候选习题。
2. 计算 `score(uid, rec, ex)`。
3. 用 `softmax(score / temperature)` 近似 Top-K 曝光概率。
4. 聚合得到期望 item exposure。
5. 通过 `Q.txt` 或新增的 `ex_has_kc` 关系矩阵聚合得到期望 KC exposure。
6. 与目标曝光分布比较，加入正则损失。

可选正则：

| 正则 | 作用 |
| --- | --- |
| `item_exposure_balance` | 降低习题曝光过度集中 |
| `kc_exposure_balance` | 降低知识点曝光过度集中 |
| `long_tail_item_boost` | 提升长尾习题期望曝光 |
| `long_tail_kc_boost` | 提升长尾 KC 期望曝光 |

第一版优先选择：

```text
loss = bce_loss + alpha_item * item_fair_loss + alpha_kc * kc_fair_loss
```

其中 `item_fair_loss` 和 `kc_fair_loss` 不直接用不可微的 Gini，而用更稳定的分布距离，例如 MSE 或 KL：

```text
item_fair_loss = MSE(expected_item_exposure, target_item_distribution)
kc_fair_loss   = MSE(expected_kc_exposure, target_kc_distribution)
```

目标分布不要一开始设成完全均匀，建议使用“平滑长尾目标”：

```text
target = normalize((popularity + epsilon) ** gamma)
```

其中 `gamma < 1` 可以削弱热门资源优势。这样比强行均匀更合理，因为教育推荐中并不是每道题、每个知识点都应该完全等量曝光。

为什么这样做：

- 与后处理的 `quota_ratio_hybrid` 相比，模型内正则可以改变底层分数分布。
- 与直接优化 Gini 相比，期望曝光分布距离更容易训练。
- 同时支持 item 和 KC 两个公平对象，符合我们当前论文主线。

建议参数默认关闭：

| 参数 | 默认值 | 含义 |
| --- | ---: | --- |
| `--fairness-loss none` | `none` | 默认不改变 baseline |
| `--fairness-alpha-item` | `0.0` | 习题公平正则权重 |
| `--fairness-alpha-kc` | `0.0` | 知识点公平正则权重 |
| `--fairness-temperature` | `1.0` | soft exposure 温度 |
| `--fairness-candidate-size` | `150` | 每批公平正则候选习题数量 |
| `--fairness-target-gamma` | `0.5` | 热门度平滑强度 |

### 4.4 阶段 D：KG-aware 推理与解释

目标：把训练阶段加入的 KG 结构反映到可解释输出中。

需要做的事情：

1. 让解释模块读取 `Q.txt` 或新增 `ex_has_kc` 边。
2. 对每条推荐输出：
   - 推荐习题；
   - 覆盖知识点；
   - 学生该知识点掌握/遗忘情况；
   - 该习题是否属于长尾习题；
   - 该知识点是否属于长尾 KC；
   - 推荐是否满足公平约束。
3. 增加解释级指标：
   - 推荐解释覆盖的 KC 数量；
   - 解释路径中长尾 KC 占比；
   - 不同学生之间解释路径多样性。

为什么这样做：

- 我们的论文目标不是单纯公平，而是保留原有可解释性。
- 如果模型内公平提升了 KC 覆盖，解释模块应该能展示“为什么这些 KC 获得更多学习机会”。
- 这能把公平性和教育意义联系起来，而不是只报告抽象数值。

## 5. 推荐的模块划分

为了避免代码继续堆积，建议按下面的深模块方式改造。

| 模块 | 主要职责 | 不应承担的职责 |
| --- | --- | --- |
| `fairness_context.py` | 读取 Q、训练三元组、构建 item/KC popularity、长尾标记、ex-kc 矩阵 | 不训练模型 |
| `prepare_fair_kg_graph.py` | 基于原图生成增强 KG 图目录 | 不修改原始数据 |
| `training_objectives.py` | 封装 BCE、关系权重、公平正则组合 | 不关心文件路径 |
| `fairness_regularizer.py` | 计算可微公平正则 | 不保存实验结果 |
| `model_interfaces.py` | 抽象 `score_triples` 和 `score_recommendations` 接口 | 不实现具体模型逻辑 |
| `explanation_fairness.py` | 输出 KG-aware 公平解释证据 | 不改变推荐列表 |

最重要的 seam 是训练目标：

```text
run_semantic_conve.py
  -> load graph/features
  -> build dataset/dataloader
  -> model.score_triples(...)
  -> TrainingObjective.compute_loss(...)
```

这样后续替换 ConvE 时，只要新模型实现相同的 scoring interface，公平正则和实验流水线仍然可以复用。

| 实验名 | 改造内容 | 目的 |
| --- | --- | --- |

| `fairkg_weighted` | fair KG + 关系 loss 权重 | 验证关系规模平衡是否影响推荐公平 |

优先判断标准：

1. Ada 下降不能过大。

5. LongTailItemExposureShare、LongTailKCExposureShare 提升。

## 8. 风险与控制

### 8.1 加 ex-kc 边可能导致训练边数进一步膨胀

控制方式：

- 记录新增边数量。
- 给 `ex_has_kc/kc_has_ex` 单独设置 loss weight。
- 必要时只加入正向边做对照。

### 8.2 公平正则可能牺牲 Ada

控制方式：

- 默认 `alpha_item=0`、`alpha_kc=0`。
- 第一轮只试较小权重。
- 和后处理 `quota_ratio_hybrid` 对比 trade-off。

### 8.3 完全均匀曝光不一定适合教育推荐

控制方式：

- 使用 popularity-smoothed target，而不是完全均匀 target。
- 同时报告 Ada/NOV，避免只为公平而破坏教学适配。

### 8.4 当前 KG 中没有真实知识点层级

控制方式：

- 第一版只用 `Q.txt` 的 ex-kc 结构。
- 不虚构先修关系、父子知识点关系。
- 后续如果要加入知识点层级，必须确认数据源或文献依据。
