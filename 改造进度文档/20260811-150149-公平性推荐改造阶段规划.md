# 2CKG4ER 公平性推荐改造阶段规划

生成时间：2026-08-11 15:01:49

## 1. 改造范围

本轮改造针对整个项目目录：

```text
E:\Fairness-aware\2CKG4ER
```

核心代码目录为：

```text
E:\Fairness-aware\2CKG4ER\Code
```

改造目标是在保留原有 2CKG4ER 可解释教育推荐能力的基础上，逐步加入公平性推荐能力。当前优先考虑：

```text
习题曝光公平
知识点曝光公平
长尾习题/KC 覆盖
公平性指标与原有效用指标的 trade-off
```

原有可解释性不删除，仍保留：

```text
学生掌握度 mlkc
习题遗忘度 exfr
习题/KC 语义信息
Ada / NOV / Ep_sim
局部解释证据导出
```

## 2. 总体改造原则

### 2.1 模块化优先

新增能力必须尽量形成独立 module，不把公平性逻辑散落到训练、测试、评估、报表脚本里。

建议新增目录：

```text
Code/fairness/
  __init__.py
  context.py
  exposure.py
  metrics.py
  rerank.py
  evaluate.py
  run_rerank.py
```

其中：

```text
context.py   负责从 raw、Q.txt、er_graph 中构造公平性上下文
exposure.py  负责统计 item/KC 曝光分布
metrics.py   负责计算公平性指标
rerank.py    负责公平性重排
evaluate.py  负责统一评价入口
run_rerank.py 负责命令行运行
```

这样后续如果把 ConvE 换成新模型，公平性评价和公平性重排仍可复用。

### 2.2 基础模型对照优先

每加入一个新 module，都要能在基础模型上单独验证，不允许多个 module 一起加入后才回头拆消融。

推荐实验顺序：

```text
Base-2CKG4ER
Base-2CKG4ER + fairness metrics
Base-2CKG4ER + item fairness rerank
Base-2CKG4ER + KC fairness rerank
Base-2CKG4ER + item + KC fairness rerank
```

后续模型改造也按同样原则：

```text
Base-2CKG4ER
+ ex-covers-kc graph edges
+ fairness-aware negative sampling
+ fairness loss
+ newer KG model backbone
```

### 2.3 文献依据优先

新增方案必须满足：

```text
有论文依据
有理论解释
优先查是否有真实公开代码
能说明该方法适合当前教育推荐/KG 推荐场景
```

不能仅凭直觉自造指标或公式。若必须提出项目自定义指标，也要说明它来自已有指标的教育场景改写，例如从 exposure fairness、catalog coverage、long-tail recommendation、popularity bias 等方向迁移。

### 2.4 输出位置清晰

实验输出不要散落在源码目录。建议：

```text
runs/<dataset>/<run-id>/2CKG4ER/seedXXXX/fairness/
```

临时测试数据在验证后删除。若需要保留实验结果，必须放到 `runs/`、`Data_Fin/<dataset>/fairness/` 或本文档目录中。

## 3. 第一阶段：只加入公平性指标

### 3.1 阶段目标

第一阶段只针对主模型 2CKG4ER，不考虑原有对比模型和消融模型。

目标是建立一个“公平性增强前的基础对照版本”：

```text
原始 2CKG4ER 训练与推荐流程不变
只在评估阶段新增公平性指标
输出原有效用指标 + 新公平性指标
形成后续所有改造方法的 baseline
```

第一阶段不做：

```text
不改 ConvE 主模型
不改 triples.txt 构造逻辑
不做公平性重排
不改对比模型
不跑全量消融
```

### 3.2 第一阶段需要新增的指标

建议先加入以下指标。

| 指标 | 方向 | 含义 | 用途 |
|---|---|---|---|
| ItemExposureGini@K | 越低越公平 | top-K 推荐中习题曝光分布的不均衡程度 | 判断是否集中推荐少量习题 |
| KCExposureGini@K | 越低越公平 | top-K 推荐覆盖到的知识点曝光分布不均衡程度 | 判断是否集中在少量 KC |
| ItemCoverage@K | 越高越好 | 至少被推荐一次的习题占全部习题比例 | 衡量习题覆盖面 |
| KCCoverage@K | 越高越好 | 至少被推荐一次的 KC 占全部 KC 比例 | 衡量知识点覆盖面 |
| LongTailItemExposure@K | 需结合 coverage/Gini | 长尾习题获得的曝光占比 | 判断长尾习题是否被照顾 |
| LongTailKCExposure@K | 需结合 coverage/Gini | 长尾 KC 获得的曝光占比 | 判断长尾知识点是否被照顾 |
| TopItemExposureShare@K | 越低越公平 | top 10% 习题占据的推荐曝光比例 | 辅助解释热门集中 |
| TopKCExposureShare@K | 越低越公平 | top 10% KC 占据的推荐曝光比例 | 辅助解释 KC 集中 |

原有指标继续保留：

```text
Ada@K
NOV@K
Ep_sim@10
```

第一阶段报告时建议采用：

```text
Utility: Ada@10, NOV@10, Ep_sim@10
Fairness: ItemExposureGini@10, KCExposureGini@10, ItemCoverage@10, KCCoverage@10
Long-tail: LongTailItemExposure@10, LongTailKCExposure@10
```

### 3.3 第一阶段需要构造的上下文

公平性指标需要以下中间信息：

```text
exercise_to_kc
item_popularity
kc_popularity
item_long_tail_flag
kc_long_tail_flag
```

定义如下：

```text
exercise_to_kc:
  由 Q.txt 得到，表示每道习题关联哪些知识点。

item_popularity:
  训练集中每道习题出现次数，来自 interactions_all.csv。

kc_popularity:
  由 item_popularity 和 exercise_to_kc 聚合得到，表示每个 KC 在训练数据中被练习的频次。

item_long_tail_flag:
  按 item_popularity 排序，不属于 top 20% 热门习题的习题标记为长尾。

kc_long_tail_flag:
  按 kc_popularity 排序，不属于 top 20% 热门 KC 的知识点标记为长尾。
```

top 20% 只是第一版默认定义，后续应在参数敏感性中检查：

```text
top 10%
top 20%
top 30%
```

## 4. 第二阶段：加入公平性改造方法

第二阶段开始改推荐结果、训练数据或模型本身。按难易程度由易到难推进。

### 4.1 方法一：后处理公平性重排

难度：低。

不改训练，不改主模型，只对 `2CKG4ER_uid_ex_scores.pkl` 做重排。

候选公式：

```text
fair_score(u, e)
  = model_score(u, e)
  - alpha * item_popularity_penalty(e)
  - beta  * kc_popularity_penalty(e)
  + gamma * long_tail_item_bonus(e)
  + eta   * under_exposed_kc_bonus(e)
```

需要新增：

```text
Code/fairness/rerank.py
Code/fairness/run_rerank.py
```

为什么先做：

```text
风险低
容易解释
和文献中的 post-processing / re-ranking 路线一致
可以直接和原始 2CKG4ER 做成对照实验
```

### 4.2 方法二：预处理数据裁剪或重采样

难度：中。

目标是减少训练正例构造阶段的曝光集中。

可选方向：

```text
限制每个习题进入 rec 正例的最大次数
限制每个 KC 在 rec 正例中的最大曝光比例
对长尾习题/KC 做补采样
对过热习题/KC 做降采样
```

要注意：

```text
不能破坏学生认知适配逻辑
不能让推荐变成只为了覆盖而覆盖
必须保留 Ada/NOV/Ep_sim 对照
```

### 4.3 方法三：知识图谱结构增强

难度：中到高。

当前 KG 虽然用三元组训练，但没有显式加入 `exercise -> knowledge concept` 边。第二阶段或第三阶段可以加入：

```text
ex -> covers -> kc
kc -> covered_by -> ex
```

可进一步加入：

```text
ex -> item_popularity_level -> pop_low/pop_mid/pop_high
kc -> kc_frequency_level -> kc_low/kc_mid/kc_high
```

为什么做：

```text
让模型训练阶段直接看到习题与知识点结构
让知识点公平不只停留在后处理和评价阶段
为后续模型级公平约束打基础
```

### 4.4 方法四：训练阶段公平性约束

难度：高。

可选方向：

```text
正样本 reweight
长尾习题/KC 正例加权
热门习题/KC 惩罚
batch 内 KC 覆盖约束
item/KC exposure regularization
```

候选 loss：

```text
loss = BCE
     + lambda_item * item_exposure_regularization
     + lambda_kc   * kc_exposure_regularization
```

更稳的第一步是样本加权：

```text
loss = BCE(pred, label) * sample_weight
```

其中：

```text
sample_weight = 1
              + long_tail_item_boost
              + rare_kc_boost
```

### 4.5 方法五：模型主干替换

难度：高。

如果后续考虑替换 ConvE，需要先抽象推荐模型 interface：

```python
train_model(graph_path, feature_path, config) -> checkpoint
score_uid_ex(checkpoint, graph_path, feature_path) -> uid_ex_scores
```

候选模型方向需要另写文档和检索文献，不能直接替换：

```text
RotatE / ComplEx / TuckER / CompGCN / R-GCN / KGIN / KGAT / LightGCN + KG
```

是否替换 ConvE，需要回答：

```text
新模型是否更适合多关系 KG
是否支持 side features
是否支持 relation strength
是否有公开代码
是否能保留 2CKG4ER 的可解释性证据
训练成本是否可控
```

## 5. 第三阶段：原有代码优化和翻新

第三阶段可以和第二阶段同步推进，但要和公平性实验分支隔离，避免基础对照被污染。

### 5.1 需要优先检查的问题

1. ConvE 是否仍是合适主干。

当前主模型使用 ConvE 风格 scoring。需要调研近几年 KG 推荐和教育推荐中更常用的模型，判断是否替换或作为新 backbone 选项。

2. `top_k_rec=10` 是否合理。

当前 `build_er_graph.py` 默认每个训练学生构造 top 10 条 `rec` 边。不同数据集规模差异很大：

```text
Eedi: 948 习题
algebra2005: 1084 习题
assist2009-sub: 1575 习题
statics2011: 633 习题
XES3G5M-sub-small: 1606 习题
```

所有数据集固定 top 10 可能不合理。需要比较：

```text
固定 top 10
按习题数比例 top p%
按学生历史长度自适应 top-k
按 KC 覆盖目标自适应 top-k
```

3. 当前 `rec` 正例构造是否过度集中。

已有统计显示部分数据集 item/KC 曝光 Gini 很高，应优先检查 `build_er_graph.py` 的 top-k 选择策略。

4. 当前评估是否过滤已做习题。

推荐任务通常应避免推荐学生已经做过的习题。需要统一支持：

```text
--exclude-seen
```

并确保主模型、对比模型和公平性重排使用同一口径。

5. 当前文档和代码命名一致性。

继续清理旧名称：

```text
SemanticConvE
feature_only
ACC
旧 pipeline 入口
```

保留必要兼容 alias，但正式输出统一用：

```text
2CKG4ER
Ada
```

6. 训练参数是否需要按数据集规模自适应。

需要检查：

```text
negative_ratio
batch_size
epochs
learning_rate
top_k_rec
embedding_dim
```

不同规模数据集完全共用一套参数，可能导致对大数据集欠训练、对小数据集过拟合。

## 9. 当前路线总结

短期路线：

```text
先只给主模型 2CKG4ER 加公平性指标。
```

中期路线：

```text
在主模型输出上做 item/KC 公平性重排，形成 Fair-2CKG4ER 第一版。
```

长期路线：

```text
扩展知识图谱结构、加入公平性训练约束、评估是否替换 ConvE 主干。
```

这条路线的优点是：

```text
不破坏现有可解释性
每一步都有基础模型对照
每个新增模块都能独立消融
先低风险得到论文结果，再推进模型级创新
```
