# 2CKG4ER 公平性推荐改进方案

生成时间：2026-08-09 19:16:08

## 1. 改进目标

当前代码实现的是 2CKG4ER 教育推荐流程：先从学生答题序列中估计 MIRT 能力、知识掌握度、知识遗忘度和习题语义特征，再构造教育推荐知识图谱，最后用特征增强 ConvE 学习 `uid -rec-> ex` 推荐关系。

后续小论文建议把工作定位为：

```text
Fairness-aware 2CKG4ER: 面向低活跃学习者与长尾习题/KC 的公平性教育推荐
```

核心问题不是重新发明主模型，而是在现有 2CKG4ER 上补齐公平性目标：

1. 用户侧公平性：低活跃学生不应系统性获得更差的推荐质量、学习收益和解释多样性。
2. 资源侧公平性：推荐结果不应过度集中到少量热门习题或少量知识点。
3. 教育解释公平性：不同学生群体获得的推荐应覆盖足够多样的知识点、难度区间和认知状态。
4. 效用与公平性的平衡：在保持 Ada、NOV、Ep_sim 不显著下降的同时，降低组间差距和曝光集中。

参考论文中的关键启发：

```text
参考论文/1.extracted.txt
公平推荐综述：公平性可在 pre-processing、in-processing、post-processing 三个阶段改进，并应报告准确性与公平性的 trade-off。

参考论文/2.extracted.txt
Fairness-Aware Explainable Recommendation over Knowledge Graphs：
按用户活跃度划分 active / inactive，发现 inactive 用户推荐性能和解释多样性更差；提出在已有 KG 推荐模型之上做公平性重排序。
```

## 2. 当前代码的不公平性来源

### 2.1 数据层：学生活跃度天然长尾

当前 raw 数据统一来自：

```text
Code/Data_Fin/<dataset>/raw 或 raw_compact/interactions_all.csv
Code/Data_Fin/<dataset>/raw 或 raw_compact/student_split.csv
Code/Data_Fin/<dataset>/raw 或 raw_compact/Q.txt
```

按每个学生交互次数统计，数据集存在明显活跃度差异。用训练学生中 top 5% 交互数作为 active，其余作为 inactive，可以直接复用参考论文 2 的用户分组思想。

本地代码与数据的初步诊断结果：

| 数据集 | 学生数 | 交互数 | 中位交互数 | P95 交互数 | 最大交互数 |
|---|---:|---:|---:|---:|---:|
| Eedi | 935 | 98,742 | 105.0 | 185.0 | 198 |
| algebra2005 | 574 | 607,025 | 574.5 | 3,630.7 | 7,021 |
| assist2009-sub | 938 | 40,330 | 35.0 | 86.0 | 142 |
| statics2011 | 331 | 113,992 | 403.0 | 594.0 | 743 |
| XES3G5M-sub-small | 968 | 331,119 | 350.0 | 381.0 | 395 |

其中 `algebra2005` 的长尾最明显，少数高活跃学生的交互远多于普通学生。当前 2CKG4ER 虽然训练时不再读测试三元组，但表示学习、正例构造和评估汇总仍然默认“所有学生平均”，没有显式照顾低活跃学生。

### 2.2 图构造层：`rec` 正例高度集中

当前关键代码在：

```text
Code/front_pipeline/build_er_graph.py
```

当前推荐距离为：

```text
distance(uid, ex) =
sqrt((delta_1 - mastery_product(uid, ex))^2
   + (delta_2 - exercise_forgetting(uid, ex))^2)
```

然后对每个训练学生取距离最小的 top-k 习题写入：

```text
uid<TAB>rec<TAB>ex
```

这个策略的优点是简单、教育意义清晰；问题是没有任何曝光约束、长尾约束或组公平约束，导致训练正例本身已经偏向少量“最接近目标掌握度和遗忘度”的习题。

本地 `er_graph/triples.txt` 中训练 `rec` 正例曝光诊断如下：

| 数据集 | 习题曝光 Gini | top 10% 习题曝光占比 | 被曝光习题覆盖率 | KC 曝光 Gini | 被曝光 KC 覆盖率 |
|---|---:|---:|---:|---:|---:|
| Eedi | 0.6709 | 0.4088 | 0.4863 | 0.3896 | 1.0000 |
| algebra2005 | 0.9738 | 1.0000 | 0.0941 | 0.9231 | 0.3929 |
| assist2009-sub | 0.8935 | 0.8449 | 0.2000 | 0.6293 | 0.9800 |
| statics2011 | 0.8518 | 0.7577 | 0.4629 | 0.7923 | 0.7629 |
| XES3G5M-sub-small | 0.9260 | 0.9036 | 0.2758 | 0.9498 | 0.2805 |

最严重的是 `algebra2005`：top 10% 习题拿到 100% 训练推荐曝光，只有 9.41% 的习题被作为 `rec` 正例。这意味着模型还没训练，训练标签已经把推荐空间压得很窄。

### 2.3 群体层：inactive 学生的候选距离更差

仍按训练学生 top 5% 交互数划分 active，其余为 inactive。统计当前 `build_er_graph.py` 生成的 top-k `rec` 正例对应的平均推荐距离：

| 数据集 | active 平均距离 | inactive 平均距离 | 观察 |
|---|---:|---:|---|
| Eedi | 0.2199 | 0.2764 | inactive 更差 |
| algebra2005 | 0.3229 | 0.6185 | inactive 明显更差 |
| assist2009-sub | 0.3533 | 0.5515 | inactive 明显更差 |
| statics2011 | 0.1958 | 0.3120 | inactive 更差 |
| XES3G5M-sub-small | 0.1478 | 0.1598 | 差距较小 |

这里的“距离更大”表示候选习题离目标掌握度和目标遗忘度更远。也就是说，当前正例构造阶段已经让低活跃学生更难得到理想推荐。

### 2.4 评估层：只报总体指标，缺少公平性指标

当前指标代码在：

```text
Code/codes-New-ConvE/evaluate_recommendations.py
Code/comparison_models/evaluate_recommendations.py
Code/codes-New-ConvE/ep_sim.py
```

当前输出：

```text
Ada
NOV
Ep_sim
```

不足：

1. 没有 active / inactive 分组指标。
2. 没有组间差距，比如 `Ada_gap = Ada_active - Ada_inactive`。
3. 没有资源侧曝光公平性，比如 item exposure Gini、KC exposure Gini。
4. 没有个体公平性，比如每个用户推荐收益分布的 Gini 或方差。
5. 没有显式过滤学生历史已做习题，可能让推荐质量和公平性同时偏乐观。

### 2.5 训练层：loss 没有公平性约束

当前训练代码在：

```text
Code/codes-New-ConvE/run_semantic_conve.py
```

核心 loss 是普通 BCE：

```text
F.binary_cross_entropy(pred, label)
```

负采样只对 `rec` 关系做类型约束 tail replacement。它保证负样本是习题实体，但没有：

1. 按用户活跃度重加权。
2. 按习题热度重采样或惩罚热门习题。
3. 按 KC 曝光稀缺度加权。
4. 对推荐分数的组间差距做正则化。

因此训练会继续学习图构造阶段已经存在的曝光偏差。

## 3. 总体改进路线

建议采用“三阶段递进”的小论文路线：

```text
阶段 A：Fairness Diagnosis
先证明当前 2CKG4ER 存在用户侧和资源侧不公平。

阶段 B：Fairness-aware Re-ranking
不改主模型，在模型输出分数上做公平性后处理重排，作为主改进方法。

阶段 C：Fairness-aware Training
在 BCE 上加入轻量 group / exposure reweight，作为增强实验或消融实验。
```

这样设计的好处是风险低、论文叙事清晰、代码改动可控：

1. 诊断层可以复用所有模型，支持主模型和对比模型公平性比较。
2. 重排层是模型无关的，能直接作用于 2CKG4ER、KGE 和 CF 对比模型。
3. 训练层只作为增强项，不会阻塞前两阶段出结果。

## 4. 建议的系统架构

按 deep module 思路，不建议把公平性逻辑散落到 `build_er_graph.py`、`test_semantic_conve.py`、`evaluate_recommendations.py` 和报表脚本里。建议新增一个小接口、较深实现的公平性模块：

```text
Code/fairness/
  __init__.py
  groups.py
  exposure.py
  metrics.py
  rerank.py
  io.py
  tests/
```

### 4.1 `groups.py`

职责：从 raw 交互记录生成公平性分组。

建议接口：

```python
build_activity_groups(interactions, split, active_quantile=0.95) -> dict
```

输出：

```text
Data_Fin/<dataset>/fairness/groups/activity_groups.json
```

建议包含：

```text
uid -> active/inactive
uid -> interaction_count
uid -> correct_rate
uid -> history_exercises
uid -> history_kcs
```

优先分组：

1. active / inactive：按学生交互数 top 5%。
2. low / mid / high mastery：按平均知识掌握度三分位。
3. cold / warm：按历史交互数阈值。

小论文主线建议只使用 active / inactive，其他分组作为附加分析。

### 4.2 `exposure.py`

职责：统计推荐列表中的资源曝光。

建议接口：

```python

```

输出：

```text

kc_exposure_count
difficulty_bucket_exposure
item_coverage
kc_coverage
item_exposure_gini
kc_exposure_gini
top_10pct_item_exposure_share
```

### 4.3 `metrics.py`

职责：在现有 Ada、NOV、Ep_sim 外增加公平性指标。

建议新增指标：

```text
Ada_active
Ada_inactive
Ada_gap = Ada_active - Ada_inactive
Ada_ratio = Ada_inactive / Ada_active

NOV_active
NOV_inactive
NOV_gap

Ep_sim_active
Ep_sim_inactive
Ep_sim_gap

UserUtilityGini
ItemExposureGini
KCExposureGini
ItemCoverage
KCCoverage
LongTailExposureShare
```

其中核心论文指标建议固定为：

```text
Performance: Ada@10, NOV@10, Ep_sim@10
User fairness: |Ada_active - Ada_inactive|, |Ep_sim_active - Ep_sim_inactive|
Resource fairness: ItemExposureGini@10, KCExposureGini@10, ItemCoverage@10, KCCoverage@10
```

### 4.4 `rerank.py`

职责：对模型输出的 `uid_ex_scores` 做公平性重排。

建议接口：

```python
fair_rerank(uid_ex_scores, context, top_k, alpha, beta, gamma, exclude_seen=True) -> list
```

输入：

```text
模型原始 uid_ex_scores
Q 矩阵
学生历史做题记录
activity_groups
习题流行度
KC 当前曝光计数
```

推荐重排公式：

```text
score_fair(u, e, rank_step)
  = score_model(u, e)
  - alpha * popularity_penalty(e)
  + beta  * long_tail_bonus(e)
  + gamma * kc_coverage_bonus(e)
  + eta   * inactive_support(u, e)
```

解释：

1. `score_model`：2CKG4ER 原始分数。
2. `popularity_penalty`：训练集中习题出现越多，惩罚越大。
3. `long_tail_bonus`：低曝光习题奖励。
4. `kc_coverage_bonus`：当前 top-k 推荐中尚未覆盖或曝光不足的 KC 奖励。
5. `inactive_support`：对 inactive 学生更重视认知适配和知识点覆盖。

也可以把当前教育距离作为后处理项：

```text
score_fair(u, e)
  = score_model(u, e)
  - lambda_d * normalized_distance(u, e)
  - alpha    * item_popularity(e)
  + beta     * under_exposed_item(e)
  + gamma    * under_exposed_kc(e)
```

这样能把 2CKG4ER 原论文的认知适配目标和公平性目标统一起来。

### 4.5 `io.py`

职责：统一读写公平性实验文件，避免每个脚本自己拼路径。

建议输出：

```text
runs/<dataset>/<run-id>/<model>/seedXXXX/fairness/
  groups.json
  reranked_uid_ex_scores.pkl
  metrics.json
  exposure.json
  tradeoff.csv
```

## 7. 代码改造注意事项

1. 不要把公平性公式硬写进 `evaluate_recommendations.py`。应新增 `fairness/metrics.py`，原始评估脚本只负责调用或保持兼容。
2. 不要直接改动 2CKG4ER 主模型结构作为第一步。先做模型无关的诊断和重排，结果更稳。
3. 所有模型的公平性评估必须共用同一套 `groups.py` 和 `metrics.py`，否则主模型与对比模型不可比。
4. `exclude_seen` 应统一用于主模型和对比模型，且在指标 JSON 中明确记录是否开启。
5. 生成的临时测试数据、debug CSV 和中间验证文件在测试后删除；需要保留的实验结果必须放到 `runs/.../fairness/` 或 `Data_Fin/.../fairness/`，不要散落在源码目录。
6. 新增测试建议使用 `tmp_path` 或系统临时目录，测试结束不向 `Code/` 保留数据文件。
7. 当前 `build_er_graph.py` 用 `shutil.rmtree(output)` 重建图目录，后续如果加入公平性图构造实验，要避免误删正式 `er_graph`。建议新增 `er_graph_fair/` 或通过 `--graph-subdir` 明确隔离。

## 8. 建议的小论文创新点表述

可以把创新点写成三条：

1. 提出教育推荐场景下的双侧公平性诊断框架，同时衡量低活跃学习者推荐收益差距和习题/KC 曝光集中。
2. 在 2CKG4ER 的认知适配推荐基础上，设计模型无关的公平性重排策略，将掌握度、遗忘度、长尾习题和 KC 覆盖统一到 top-k 选择过程中。
3. 在五个教育数据集上验证公平性与推荐效用的 trade-off，证明公平重排可以降低 active/inactive 差距并改善知识点覆盖，同时保持 Ada、NOV 和 Ep_sim。

建议论文标题：

```text
Fair-2CKG4ER: Fairness-aware Educational Recommendation over Cognitive Knowledge Graphs
```

中文标题：


## 10. 优先级结论

最高优先级：

```text
先实现公平性诊断和公平性重排。
```

原因：

1. 当前不公平性最强的证据出现在推荐正例和 top-k 曝光层。
2. 后处理重排不破坏现有 2CKG4ER 主流程，能快速出实验结果。
3. 该方向与参考论文 2 的 KG 公平推荐思路最一致，也更容易形成小论文叙事。

不建议第一步就改模型主体。模型结构改造可以作为第二阶段增强实验，否则容易把论文贡献、代码风险和实验变量混在一起。
