# 可能有错误与待改进优化的地方

生成时间：2026-08-09 18:07:02  
更新说明：已按本轮清理结果标记已处理项，并保留后续公平性改进方向。

## 1. 已处理的问题

### 1.1 主模型命名

旧代码中正式主模型长期显示为 `SemanticConvE` / `feature_only`，容易和论文 2CKG4ER 不一致。当前已改为：

```text
2CKG4ER
2CKG4ER_id_only
2CKG4ER_relation_id
2CKG4ER_learner_id
2CKG4ER_exercise_id
2CKG4ER_no_mastery
2CKG4ER_no_forgetting
```

旧名仅作为历史结果读取或代码兼容 alias。

### 1.2 训练阶段加入测试三元组

旧代码曾有 `--include-test-triples` / `--exclude-test-triples`。当前已删除该命令选择，正式协议固定为：

```text
训练只读 triples.txt
test_triples.txt 只用于测试/评价
```

这能降低测试学生认知状态边泄漏到训练阶段的争议。

### 1.3 ACC 与 Ada 命名

旧代码输出 `ACC`，但论文中对应的是 `Ada` / Adaptability。当前新评价结果输出 `Ada`；汇总脚本保留对历史 `ACC` JSON 的读取兜底。

### 1.4 raw 与 raw_compact 误读风险

当前代码已固定：

```text
assist2009-sub -> raw_compact
XES3G5M-sub-small -> raw_compact
其他数据集 -> raw
```

`front_pipeline/common.py` 和 `raw_pipeline/validate_raw_datasets.py` 会拒绝不符合该规则的 `--raw-name`。

### 1.5 v11_pipeline 旧实现复用

原先 `front_pipeline/train_ektm_mirt.py` 会动态加载 `v11_pipeline/train_ektm_mirt_v11.py`。当前已把必要组件迁移到：

```text
front_pipeline/ektm_mirt_components.py
```

旧 `v11_pipeline` 源码入口已删除。

## 2. 仍建议优先改进的问题

### 2.1 评价时可能未过滤已做过的习题

论文推荐任务通常强调“推荐未尝试过的习题”。当前 `evaluate_recommendations.py` 主要按分数取 top-k，未显式过滤每个测试学生历史已做题。

建议新增：

```text
--exclude-seen
```

并统一用于 2CKG4ER、KGE 和 CF 模型。

### 2.2 推荐正例构造高度集中

当前 `build_er_graph.py` 为每个训练学生选择认知距离最小的 top-10 习题作为 `rec` 正例，未加入覆盖率或长尾约束。前期诊断显示，部分数据集 rec 题目暴露非常集中，尤其 `algebra2005`。

建议加入公平感知正例构造：

```text
distance_fair = distance_cognitive
              + alpha * popularity_penalty
              - beta * long_tail_bonus
              - gamma * kc_coverage_bonus
```

### 2.3 低活跃学生系统性处于劣势

已诊断到低活跃学生的 top-10 认知距离通常更大，说明不公平性在模型训练前的候选构造阶段已经出现。

建议增加：

```text
active/inactive Ada gap
active/inactive NOV gap
active/inactive Ep_sim gap
```

并在重排序或训练 loss 中对低活跃学生加权。

### 2.4 缺少 item/KC exposure fairness 指标

当前只报告整体 Ada、NOV、Ep_sim，尚未报告题目或知识点暴露是否集中。

建议新增：

```text
item exposure Gini
KC exposure Gini
item coverage
KC coverage
difficulty bucket exposure
```

### 2.5 `mastery_product` 可能惩罚多知识点习题

`build_er_graph.py` 当前用多个知识点掌握度连乘计算习题掌握项。多知识点题会天然更难达到目标掌握度，可能导致曝光不足。

建议比较：

```text
product
mean
geometric mean
min
```

并统计多知识点习题的推荐曝光。

### 2.6 训练损失尚未做 group-balanced loss

`run_semantic_conve.py` 当前使用整体 BCE，未按学生活跃度、题目热度或知识点频率进行公平性重加权。

建议后续加入：

```text
--fairness-group-file
--group-loss-reweight
--inactive-weight
```

先做公平性评价和后处理重排序，再考虑改训练损失，风险更低、论文叙事也更清晰。
