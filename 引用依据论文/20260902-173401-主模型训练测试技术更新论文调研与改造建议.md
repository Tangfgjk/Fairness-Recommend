## 1. 本次调研目标

本次调研只针对当前 2CKG4ER 的主模型训练与测试部分进行技术更新判断，不改动前置文件生成流程，也不替换当前已经整理好的基准模型与公平性指标流水线。

当前代码中的主模型 `TwoCKG4ER` 位于：

- `E:\Fairness-aware\2CKG4ER\Code\codes-New-ConvE\semantic_conve_model.py`
- 训练入口：`E:\Fairness-aware\2CKG4ER\Code\codes-New-ConvE\run_semantic_conve.py`
- 测试入口：`E:\Fairness-aware\2CKG4ER\Code\codes-New-ConvE\test_semantic_conve.py`

从代码看，当前 2CKG4ER 的主体仍是 ConvE 风格的知识图谱链接预测模型：实体和关系先通过 ID/特征融合得到 embedding，然后用 ConvE 卷积打分函数预测 `(student, rec, exercise)` 等三元组是否成立。训练时主要使用 pointwise BCE loss 与随机负采样；测试时对每个学生遍历候选习题，调用 `score_tails` 得到推荐分数，再由后续脚本计算 Ada、NOV 与公平性指标。

这说明当前代码“用了知识图谱”，但使用方式偏旧：它更像把教育推荐问题转成三元组打分，而不是近几年主流的图神经网络传播、序列知识追踪、对比学习、排序优化或 LLM 语义增强式教育推荐。

## 4. 当前 2CKG4ER 主模型的主要落后点

### 4.1 ConvE 打分函数偏旧

当前 `TwoCKG4ER` 的核心仍是 ConvE 风格的三元组打分。ConvE 是 2018 年左右的 KG link prediction 经典模型，优点是简单、参数效率较高，但它本质上是局部三元组打分，并不显式传播多跳图结构，也不直接服务 Top-K 推荐排序目标。

更新判断：

- 保留 ConvE 作为 `baseline_conve`。
- 新增可选主干 `CompGCN`，在同一张教育 KG 上做多关系消息传播。
- 后续再考虑 `NBFNet` 或 `Graph Transformer`，但不建议第一步直接大改。

### 4.2 当前“知识图谱”没有充分发挥图传播作用

当前代码确实使用了知识图谱：`triples.txt` 中包含学生、习题、知识点和多类关系，模型学习实体与关系 embedding。但是训练方式更接近 KGE 链接预测，没有将学生-习题-知识点的高阶邻居结构显式聚合。

这会带来两个问题：

- 对知识点覆盖和长尾习题的表达不够强，模型容易继续偏向热门节点。
- 可解释性依赖 embedding 或构图关系，但缺少“为什么这个知识点通过哪些路径影响推荐”的传播依据。

更新判断：

- 首选 CompGCN：它直接面向多关系图，适合复用当前 `entities.dict / relations.dict / triples.txt`。
- 中期可加 KGCL：对 KG 进行增强/去噪，并用对比学习减轻长尾节点稀疏问题。

### 4.3 训练目标仍以 pointwise BCE 为主，和 Top-K 推荐目标不完全一致

当前训练流程对三元组做二分类，使用 `weighted_bce_loss`，负样本主要来自随机负采样。这个目标能学“某个三元组是否成立”，但推荐系统最终评估的是 Top-K 排序、Ada、NOV、公平曝光、覆盖率。

最新图教育推荐和图推荐方法里，BPR、pairwise ranking、contrastive learning、listwise/top-K-aware loss 更常见。KLU4EduRec 对图教育推荐任务的形式化中，也将学习者-资源推荐写成 top-k 资源预测，并采用 BPR 形式优化正负资源排序。

更新判断：

- 第一版训练更新：在现有 BCE 基础上新增 `ranking_loss=bpr`，保留 `bce` 可选。
- 负采样从纯随机扩展为 `random + popular + hard_negative` 混合。
- 公平性 loss 从当前 expected exposure MSE 进一步改成更接近 Top-K 曝光的 listwise/soft-rank 形式。

### 4.4 学生状态建模仍偏静态

当前模型使用了 MIRT、MLKC、forgetting 等前置特征，但主模型训练本身没有端到端地建模学生历史答题序列。近年来 KT 方法，如 AKT、SAINT+、simpleKT、DTransformer、UKT，都强调根据学生历史交互动态估计知识状态。

更新判断：

- 不建议推翻现有前置特征。
- 建议新增 `student_state_encoder` 模块，让模型可选：
  - `static_feature`：当前版本。
  - `simplekt_state`：用历史序列得到学生状态。
  - `dtransformer_state` 或 `ukt_state`：后续增强。
- 这样不会破坏现有数据流，也方便消融实验。

### 4.5 语义建模偏早期

当前代码包含共享文本 BiGRU 和文本特征融合，这在早期方法中合理，但最新教育推荐开始更重视预训练语言模型或 LLM 作为语义增强器。KLU4EduRec 和 ExRec 都说明：LLM 更适合作为资源知识、知识点说明、学习路径理解的增强模块，而不是直接替代专业推荐模型。

更新判断：

- 不建议把主模型直接换成 LLM。
- 建议把 LLM/预训练文本模型用于：
  - 生成习题语义摘要；
  - 生成知识点解释；
  - 生成学生学习路径摘要；
  - 将这些摘要编码为 frozen semantic embedding，再输入 KG/GNN 推荐模型。

### 4.6 测试与评估应从“导出分数”升级为“统一推荐评估协议”

当前 `test_semantic_conve.py` 主要负责导出 `uid -> exercise scores`。实际评估由后续脚本完成。这个流程可运行，但论文实验需要更清晰的协议：

- 是否过滤训练集中已做过的习题；
- 是否所有学生都有同一候选集；
- Top-K 的 K 是否固定为 10/20/50 用于论文主表；
- Ada、NOV、公平性指标是否统一从同一份 score 文件计算；
- 重排序方法是否只作用测试阶段，不参与训练。

更新判断：

- 保留当前导出分数模式。
- 增加统一评估入口，将推荐质量、公平性和重排序结果一并汇总。
- 明确主表固定 Top-10、Top-20、Top-50，完整曲线仍保留 5-100 间隔 5。

## 5. 推荐的技术更新路线

### 路线 A：低风险主干更新，优先推荐

目标：把旧 ConvE 主干升级为多关系 GNN 主干，同时保持当前数据文件、训练脚本和评估脚本基本兼容。

建议版本名：

`v2-mainmodel-compgcn-bpr`

建议做法：

1. 新增模型注册机制：
   - `--model-backbone conve`
   - `--model-backbone compgcn`
   - 后续可扩展 `nbfnet`、`kgcl`、`graph_transformer`
2. 新增 `CompGCNEncoder`：
   - 输入仍是当前实体、关系、三元组；
   - 先做多关系图传播；
   - 再用 ConvE/DistMult/inner product 打分。
3. 新增排序损失：
   - `--ranking-loss bce`
   - `--ranking-loss bpr`
   - `--negative-sampler random|popular|hard|mixed`
4. 继续保留当前公平性指标和后处理重排序。

为什么优先做这条：

- 与当前代码结构最接近；
- 不需要重做前置数据；
- 能把论文方法从“旧 ConvE KGE”升级为“教育 KG 多关系图推荐”；
- 方便做消融：`ConvE+BCE` vs `CompGCN+BCE` vs `CompGCN+BPR` vs `CompGCN+BPR+fair_loss`。

### 路线 B：中期增强，KG 对比学习与去噪

目标：针对教育 KG 中长尾习题、低频知识点、噪声边的问题，引入 KGCL/KGTN 类思想。

建议版本名：

`v3-mainmodel-kgcl-denoise`

建议做法：

- 对 KG 做边 dropout / 节点关系增强；
- 构造两视图 embedding；
- 对学生、习题、知识点表示做 contrastive loss；
- 与公平性目标结合，减少热门习题支配。

为什么不是第一步：

- 实现复杂度高于 CompGCN；
- 需要仔细设计 KG 增强策略；
- 若先没有 GNN 主干，对比学习收益可能不稳定。

### 路线 C：学生状态编码器更新

目标：让模型不只用静态学生特征，而是用学生历史交互序列得到动态知识状态。

建议版本名：

`v4-mainmodel-kt-state`

建议做法：

- 保留当前 MIRT/MLKC/FRKC 作为输入特征；
- 新增 `student_state_encoder`：
  - `static`：当前逻辑；
  - `simplekt`：强 KT baseline；
  - `akt` / `dtransformer` / `ukt`：后续可选；
- 最终学生 embedding = 静态特征 embedding + 动态 KT 状态 embedding。

为什么值得做：

- 教育推荐的核心不是普通商品推荐，而是要判断学生当前掌握状态；
- 最新 ExRec、KLU4EduRec、UKT 等方向都强调学习路径或知识状态；
- 能保留原模型可解释性，并提升教育合理性。

### 路线 D：语义增强，但不直接替换为 LLM

目标：更新当前 BiGRU 文本编码，加入更强的习题/知识点语义表示。

建议版本名：

`v5-semantic-enhancer`

建议做法：

- 使用 frozen sentence embedding 或 LLM 生成摘要；
- 对习题题干、知识点、学习路径生成语义表示；
- 用 adapter 将语义向量映射到推荐模型空间；
- 与 KG 结构 embedding 融合。

注意：

- 不建议把推荐模型直接换成 LLM；
- 2026 年相关研究也提示，专门 KT 模型在 KT 预测上仍可能优于直接使用 LLM；
- 因此 LLM 应作为 enhancer，而不是主模型本身。

### 路线 E：公平性 loss 再升级

目标：让模型内公平性真正影响 Top-K 推荐，而不是只在后处理阶段明显。

建议版本名：

`v6-topk-fair-loss`

建议做法：

- 当前 expected exposure MSE 保留为 baseline；
- 新增 soft top-k exposure loss；
- 候选池从随机候选扩展为 `random + popular + hard + current-top-score`；
- 对 item 和 KC 同时做曝光目标约束；
- 与 BPR/listwise ranking loss 联合训练。

为什么必要：

- 阶段二已有实验显示，仅放大 `alpha/gamma` 效果有限；
- 原因可能是 fairness loss 尺度、候选池和最终 Top-K 曝光不一致；
- 所以要让训练时看到更接近测试排序的候选池。

- LongTailItemExposureShare@10/20/50
- LongTailKCExposureShare@10/20/50

完整曲线仍保留 Top-K = 5, 10, 15, ..., 100。

## 7. 结论：哪些必须更新，哪些暂缓

### 必须更新

1. ConvE 主干需要升级：至少加入 CompGCN 作为新的主模型候选。
2. 训练目标需要升级：加入 BPR/pairwise ranking，不再只依赖 BCE 三元组分类。
3. 负采样需要升级：从纯随机扩展到热门/困难/混合负样本。
4. 测试评估要规范化：固定论文主表 K=10/20/50，完整曲线仍保留。
5. 公平性 loss 需要向 Top-K 曝光靠近：否则模型内公平性不如后处理明显。

### 建议更新

1. 引入 simpleKT/AKT/DTransformer/UKT 类学生状态编码器。
2. 引入 KGCL/KGTN 类对比学习和去噪机制。
3. 引入 LLM/预训练语义 embedding，但只作为语义增强器。

### 暂缓更新

1. 不建议第一步直接做 RL 习题推荐。ExRec 很新，但改造成本大，且会改变实验问题定义。
2. 不建议直接把主模型替换为纯 LLM。现有依据更支持 “LLM-as-enhancer”。
3. 不建议第一步做 ULTRA 这类 KG foundation model。它适合远期拓展，不适合作为当前小论文第一版主干。

## 8. 下一步建议

建议下一步先设计并实现 `v2-mainmodel-compgcn-bpr`：

- 不动 `Data_Fin` 前置文件；
- 不动原 ConvE baseline；
- 新增模型注册与可插拔主干；
- 新增 CompGCN 编码器；
- 新增 BPR 训练选项；
- 保留当前公平性指标、后处理重排序、阶段一二实验结果；
- 用 Eedi seed=2024 做首轮对比。

这样更新后的论文叙事会更清楚：

1. 原模型提供可解释教育 KG 推荐基础；
2. 阶段一发现并量化习题/知识点曝光不公平；
3. 阶段二加入后处理和模型内公平性；
4. 新阶段将旧 ConvE/KGE 主干升级为更现代的教育 KG 图推荐模型；
5. 最后比较准确性、创新性、公平性和可解释性之间的权衡。
