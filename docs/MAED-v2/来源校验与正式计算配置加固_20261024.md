## 2. 检查点保护

新增独立 `source_hash` 和完整 `contract`；原 `contract_hash` 对完整合同计算摘要。模型构建前检查：

1. checkpoint 类型及收据是否完整；
2. 独立源码指纹、合同内源码指纹是否均等于当前实现；
3. 合同摘要是否一致，调用者传入预期合同摘要时是否匹配；
4. 方法、配置、资产摘要是否与合同一致；
5. 教育状态、分块、seed 是否一致；
6. 构建模型后，传播基图 ID 和模型状态结构是否匹配。

单个 checkpoint 自带收据，搬动文件不需要相邻 `run_config.json`，也不需要伪造当前源码身份。缺少收据的旧 checkpoint 明确拒绝，不能为复用权重静默补填当前源码。该机制用于可信本地实验文件的复现保护，并非对恶意 PyTorch 序列化文件的安全沙箱。

温度缓存与机制缓存即使已存在，也先验证 checkpoint 来源。分数元数据记录来源、合同和实际编码模式，正式入口拒绝复用非 full 的缓存。
