# 频率去偏实现与一键运行说明（2026-10-22）

代码位于 `Fairness-Recommend-New`，开发分支 `merit-frequency-20261022`，基于原始提交 `99068a9`。原 KG4ER-New 和旧 Fairness-Recommend 未修改。此次没有启动正式实验训练，没有提交或推送。

**已完成**

- `debias/context.py`：正式三数据集、rec50 图、学生划分、Q、全精度教育距离、历史答对 KC、原 Ada 掌握度口径及输入哈希。
- `debias/pair_matching.py`：训练正例内匹配、固定测试规则 Top-50 匹配池、按学生/频率差分层的 E3、固定随机方向 E4、属性差异和高曝光题覆盖审计。
- `debias/metrics.py`：Ada、KG4Ex-NOV-Set、CFP、DED、Item/KC Gini/Coverage、有序/无序列表比例、列表 Jaccard 差异、规则和基线重合率。
- `debias/objectives.py` / `scoring.py`：按学生平均的 logit 平方 Hinge；独立题对采样器；冻结 BN、关闭 Dropout 且保留 autograd；异常安全模式恢复。
- `debias/training.py`：复用原模型、数据加载和负采样，保持原 BCE、Adam、批大小、轮数；零权重完全跳过公平分支；每 epoch 保存优化器/全局 RNG/公平采样器状态；best 按原 BCE 选择。
- `debias/evaluation.py`：新结果直接调用冻结 Ep 模拟器计算 threshold=0.5，保存完整学生级结果；教育指标按学生配对 bootstrap，曝光指标在学生重采样后重新计算分布。
- `debias/report.py`：每数据集每指标一张 HTML 表，CSV 汇总；单种子无标准差，多种子均值±样本标准差；适用指标最佳加粗、次优下划线，规则参照不参与标优，CFP 等诊断指标不机械标优。
- `scripts/run_merit_debias_suite.py`：E0–E4 和 R 一键运行、计划预览、阶段隔离、续跑与配置一致性校验。

原模型唯一评分变更是在 `semantic_conve_model.py` 抽取 `score_logits()`；原 `score_triples()` 仍返回 `sigmoid(logit)`，参数名称不变。原训练脚本保持原样。新训练器复用其模型构建、TripleDataset 和工具；对照测试逐值验证原 BCE 一步更新。

**本次已准备的数据和基线**

三数据集九份原模型基线的 config、best.pt、原评分、推断说明及指标已独立复制到 `artifacts/baseline_original/`，共 54 个文件（含来源清单），约 435 MiB。每个源文件与副本 SHA-256 一致。来源路径仅用于追溯，后续运行无需再读取原目录。

`artifacts/debias_context/<dataset>/` 保存固定题对、训练 rec 频率、匹配审计、原负采样次数、三种子统一基线指标和中文诊断摘要。基线 Ada 已与原归档结果核对；KG4Ex-NOV-Set 与公平指标重新计算。基线 Ep 复用同一份经哈希核验的原分数对应 Ep@0.5；本次未重复执行九次完整 Ep 模拟。新实验会重新计算 Ep。

| 数据集 | 训练匹配学生/全部训练学生 | 固定 CFP 测试学生/全部测试学生 | 训练题对 |
|---|---:|---:|---:|
| Eedi | 257/701 | 85/234 | 36564 |
| Algebra2005 | 214/430 | 60/144 | 19905 |
| XES | 673/727 | 226/241 | 103826 |

Ada、NOV、Ep、曝光和覆盖指标使用完整测试人群；CFP 仅在匹配子人群计算。seed2024 原 Top-10 曝光落在“训练匹配题对高频侧题目”的质量比例分别为 100%、100%、99.88%。这只是题目层面的可触达性，不代表约束覆盖所有学生；Algebra2005 部分最高曝光题只出现在 4–5 名训练学生的匹配池中。

匹配仍固定为距离差≤0.02、掌握度乘积差≤0.05、遗忘度差≤0.05、KC 数相同、log(1+rec频率)差≥log(2)。没有为了增加数量放宽条件。难度、区分度和 KC 内容差异仅审计，未强制匹配；不能把匹配题对称为教育价值完全相同。

**一键运行**

在 Windows PowerShell 中执行：

```powershell
$repo = 'C:\Users\21709\Desktop\Fairness-Recommend\Fairness-Recommend-New'
$py = 'C:\Users\21709\.conda\envs\rtx5060\python.exe'
Set-Location -LiteralPath $repo
& $py -u .\scripts\run_merit_debias_suite.py
if ($LASTEXITCODE -ne 0) { throw '实验中断；检查错误后使用同一条命令续跑' }
```

默认数据顺序 Eedi → Algebra2005 → XES；每个数据集按种子 2024、2025、2026 运行 E0、E1、E2、E3、E4、R。E0/E1/E3/E4 训练，E2/R 仅评分与评价。总计 36 次模型训练、54 个执行阶段。所有训练使用原 25 epochs、bs=1024、lr=0.001、negative_ratio=5、feature_only，按各自归档 config 还原其他设置。

按方案先检查一个种子时，只需：

```powershell
& $py -u .\scripts\run_merit_debias_suite.py --seeds 2024
```

这会执行 12 次模型训练和 6 次无需训练的阶段。随后执行默认完整命令，会复用已完成阶段，并补充其余两个种子。`--plan` 只打印计划，不训练、不运行新模型评价：

```powershell
& $py .\scripts\run_merit_debias_suite.py --plan
```

**当前预登记初始设置**

公平权重 `--weight 0.1`、正 margin `--margin 0.1`、E2 概率分数校正强度 `--score-penalty 0.1`。这些是工程验证后锁定的探索起点，不是已通过实验选出的最优参数。`m=0` 用独立 run-id 作为机制探针：

```powershell
& $py -u .\scripts\run_merit_debias_suite.py --seeds 2024 --margin 0 --run-id merit_frequency_m0_20261022
```

不同 margin、权重或代码版本必须使用不同 run-id。不能只挑测试指标最好的设置作为事先选定的方法。E3 的频率差分层宽度为 0.25（log1p 空间），每学生各层题对数与 E1 完全一致；连续频率差仍可能存在小幅残余差异，审计保留均值和分位数。

**产物及续跑**

- 模型、best/last 检查点、逐 epoch 指标、评分、评价：`runs/merit_frequency_20261022/<dataset>/<method>/seed<seed>/`。
- 当前阶段和状态：`runs/merit_frequency_20261022/status.json`。
- 每组完整控制台输出和报错：其 `seed<seed>/stage.log`，续跑时追加。
- 论文表格：`runs/论文格式文档统计/merit_frequency_20261022/`。
- 运行配置：`protocol.json`、每组 `run_config.json`；模型、分数、指标与完成标记均有一致性检查。

同一条命令自动续跑，已完成阶段核验后跳过。训练从最后一个完整 epoch 恢复；中断的未保存 epoch 会重做。完成训练但评价失败时，只续做评分/评价。修改代码或配置后拒绝使用旧完成标记混合结果。数据文件、归档权重和大结果由 .gitignore 排除，复制项目到另一台机器时需另外拷贝 `Data_Fin_New` 和 `artifacts`。

可随时重建已完成阶段的表格：

```powershell
& $py .\scripts\report_merit_debias.py
```

HTML 可在浏览器打开并打印为 PDF；本版自动输出 HTML 和 CSV。部分完成时，各表明确展示实际存在的种子。

**验证命令和边界**

```powershell
& $py -m unittest discover -s tests -v
```

测试包括：原概率与新增 logit 一致性、λ=0 原 BCE 更新和 RNG 逐值一致、联合 BCE/公平反向传播、学生/习题/ConvE 梯度、BN 缓冲和异常模式恢复、采样器状态恢复、E3 分层平衡、NOV 集合计算、CFP 并列和空池、DED/Gini 小例子，以及真实 Eedi 检查点公平梯度和冻结 Ep 单学生五题接口检查。

真实检查点测试只前向/反向，不执行参数更新。另用两条合成三元组验证真实训练器的两 epoch 中断/恢复，恢复后参数、loss 和采样器状态与不中断执行一致；该测试不使用正式实验数据，临时检查点自动清理。没有跑任何完整 E0–E4 训练。对新方法是否有效尚无结论。三数据集、多种子完整训练耗时和运行期显存仍需正式运行测量；CPU 工程回归不能保证 CUDA 训练逐位确定。
