# 公平分支 CUDA GRU 反向传播报错修复（2026-10-22）

本次中断在 18 阶段中的第 2 阶段：Eedi / seed2024 / E1 第一批反向传播。此前 E0 的 25 轮训练、评分和评价均已完成；训练用时约 1350 秒（22.5 分钟）。E1 未完成一个 epoch，尚无训练检查点。

报错为 `RuntimeError: cudnn RNN backward can only be called in training mode`。公平分支为冻结 BatchNorm、关闭 Dropout 而临时使用 eval 行为，但原模型可训练的共享文本 BiGRU 也因此进入 cuDNN 推断路径。该路径不保留反向传播需要的 reserve space，即使恢复 model.train()，之前已执行的前向仍不能反向。

修复在 `debias/scoring.py::pair_logits`：仅在公平分支前向期间关闭 cuDNN，使用支持 eval 状态求导的原生实现，继续保留 autograd，维持冻结 BN 和 Dropout 的设计。上下文结束即恢复后端设置；原 BCE 前向仍沿用其训练模式和后端。

之前 CPU 测试和不含 GRU 的小模型测试无法发现这一 CUDA 专用限制。新增真实 Eedi 模型、共享 GRU 的 GPU 联合 BCE/公平反向测试，修复前稳定复现同一错误，修复后通过；同时检查文本编码器梯度、ConvE 梯度、BN 缓冲及模式恢复。此次只执行工程验证，没有启动正式 E1 训练。

为了保留已完成 E0，已使用 `scripts/repair_cudnn_eval_resume.py` 对已确认的旧源码版本到修复版做一次性迁移：只更新协议、E0/E1 配置及 E0 评价来源的版本元数据。原元数据备份在 `runs/merit_frequency_20261022/repairs/cudnn_aux_backward_20261022/before/`，审计记录在同目录 `migration.json`。E0 的 best.pt、last.pt、概率分数和 logit 文件 SHA-256 均保持不变；原计算来源保存在备份和指标 source_repair 中。E1 无检查点，因此修复后从第 1 轮开始；已训练的其他公平组不允许用这个迁移脚本直接兼容。
